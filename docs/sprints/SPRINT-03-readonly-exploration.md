## 交付记录

- 主任务启用文件工具时可用 `explore_files`。子请求只接收探索问题和一至四个文件的带行号摘录，返回最多 4 KiB 的摘要。单并发可完成父请求、子请求、父任务续答三次调用。
- 子请求使用父任务的项目、路由与预算，每次实际发送都登记回执。项目预算耗尽时，子请求停在派发前。派发后取消则登记未知结果，恢复任务时会提示上次探索可能已产生用量。
- CLI 在标准错误上显示探索路径及摘要状态。实际 `coda ask` 子进程测试验证了管道标准输出中，探索前后的正文可以直接拼接。

## S3-T2 · Streamable HTTP 工具客户端

| 负责组 | 交付与验收 |
| --- | --- |
| Tech-Provider | HTTP 握手、JSON/SSE 响应、会话 ID 与协议版本、超时和关闭。 |
| Tech-Runtime | 将 HTTP 工具纳入 Host 登记、工作区隔离、会话池与工具审批；保留 stdio 公共接口兼容性。 |
| Tech-CLI | 在工作台审批预览中显示实际远程目的地。 |
| QA-Gate、PM | 使用回环模拟服务验证真实 CLI/Engine 发现与授权调用，涵盖流式响应、会话复用和错误后的派发次数。 |

Host 按工作区登记远程 MCP 端点。模型发现工具时绑定目标，CLI 直接显示对应审批记录里的地址。拒绝审批或登记目标变化时不会向替代服务派发；已派发的调用遇到断流时记录结果未知。同一会话复用工具目录，支持 JSON、SSE 和分页。[配置示例](../../README.md#接入远程-mcp-工具)

### S3-T3 交付与验证

Host 使用 `CODA_KEY_POOLS` 将备用凭据绑定到路由及完整服务地址。任务推理、只读探索、模型发现和路由检查共用进程内轮询和冷却。每次尝试重新获取实际凭据的并发许可；有多个成员时，网络回执用 `credential_slot` 标识本次发送所选的成员。[配置示例](../../README.md#为同一路由配置多个账号)

| 检查 | 实测结果 |
