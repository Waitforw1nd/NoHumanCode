# 🍑sh 前端框架与已确认产品决策

日期：2026-09-21  
状态：实施决策，尚不代表界面、审批、Team 计划或 Key 健康池已交付。  
主方案：[项目逻辑与架构重整](PROJECT-REORGANIZATION-2026-09-21.md)

## 选择

采用 **Rust 宿主 + Leptos CSR/WASM 前端 + 独立 protocol crate**。先建立共享协议，再逐页替换当前网页。现有 Axum 继续提供本机 HTTP/SSE API 和构建后的静态资源；首阶段不引入 SSR，不要求新增桌面封装。

“先建立 protocol crate”与“选择 Leptos”是两个独立决策：前者解决前后端契约，后者解决界面组件和状态展示。协议不依赖 Leptos，未来更换 UI 也应复用相同契约。

## 官方资料与取舍

| 选项 | 官方资料能确认的能力 | 对本项目的判断 |
| --- | --- | --- |
| Leptos CSR | CSR 应用可构建为静态资源并由静态服务部署。[官方 CSR 部署文档](https://book.leptos.dev/deployment/csr.html) | 当前是浏览器访问本机 Axum 服务，静态界面与独立 API 的部署路径直接匹配，因此选用 |
| Dioxus Web | Rust UI 可编译为 WASM，使用浏览器 API；官方另有桌面与移动平台路径。[官方 Web 文档](https://dioxuslabs.com/learn/0.7/guides/platforms/web/) | 同样能实现当前目标；将来若跨平台原生界面成为主要需求，可重新评估，但不是当前必需范围 |
| protocol crate | 本项目的工程边界，包含共享传输类型、版本和错误契约 | 必须先做；与 UI 框架无绑定，不放数据库、凭据和宿主工具实现 |

以上选择基于产品范围与现有架构的匹配，未进行两个框架的性能对比，不据此宣称 Leptos 更快、更小或 Dioxus 不稳定。Leptos、Trunk、wasm-bindgen 以及 Rust 工具链的确切版本在 UI 实现时核对兼容性并锁定；本文件不把文档路径中的版本当成依赖版本承诺。

## 浏览器与宿主的边界

```text
Leptos UI（Rust → WASM）
    │ HTTP 命令 / SSE 事件，共享 protocol 类型
    ▼
Axum Rust Host
    ├─ 项目、会话、调度、审批和预算
    ├─ 文件、命令、Git、网络和持久化
    └─ Provider Key / New API 令牌 / DPAPI
```

Rust/WASM 前端仍需要 HTML、CSS、WASM 加载器及浏览器绑定。Leptos 官方说明，浏览器能力通过 wasm-bindgen/web-sys 与 JavaScript 环境衔接；因此目标是界面逻辑以 Rust 为主，不能承诺产物中没有任何 JavaScript。[官方浏览器绑定说明](https://book.leptos.dev/web_sys.html)

前端不能持有 Provider Key、数据库或系统执行权限。只通过宿主验证的 API 操作。插件 WASM 与 UI WASM 分属两个边界：已有无 import 的 JSON 插件运行器不能代替浏览器界面，也不自动获得宿主工具能力。

## 已确认的权限与 Team 行为

- 项目范围内的只读文件能力自动允许；写入、命令和按需网络操作逐次请求批准。
- 审批须绑定实际路径、命令、工作目录或网络目标；参数变化后重新审批。拒绝、超时或用户停止不能继续执行该操作。
- 配置模型端点和提交模型任务时，明确告知必需的 Provider 请求范围。代理额外使用网页、下载等网络工具时单独批准；更换目标或重定向到授权范围外不能沿用旧授权。
- 普通进程可能自行联网、访问磁盘。若尚无操作系统级限制，命令审批界面必须说明运行权限，不能把“网络工具要审批”描述成已强制隔离所有网络。
- Lead 先生成可审阅计划，列出成员、工作项、模型、工作区、并发和预算；用户确认后才能派工。批准计划不替代成员的逐次工具审批。
- shared/worktree 由用户选择。缺少 Git 等前提时说明不能使用 worktree，不静默改成 shared；shared 模式仍需处理写入冲突。

这些是待实施的行为契约。现有工具开关不等同于持久化的逐次审批系统；现有依赖图调度也不等同于具备确认环节的 Lead 编排。

## Key 健康、冷却与预算

启用健康度选择、限流冷却和任务预算。路由先匹配模型能力和用户约束，再从可用 Key 中选择；鉴权失败、限流、暂时故障分开记录。重试必须有次数、时间和取消上限，不能对结果不明的副作用自动重放。

预算分清三类数据：账户余额、Key 额度和任务消耗。账户余额不能直接作为任务精确费用。价格、币种或 usage 缺失时标记未知，不显示零成本，也不能伪造金额硬上限。先实现请求数、输出 token、轮数、并发和时间限制；可靠计价可用后，再通过预留额度及结算实现可验证的金额上限。未知计价时，用户选择的金额硬预算任务不能悄悄退化为无限运行。

## 迁移步骤与验收

1. **本轮首批改动**：共享协议、显式 chat/team 字段、schema 5 修正名称推断迁移与兼容测试。这是类型与迁移基础，不是完整 Session/Agent 重构。
2. **界面骨架**：建立 Leptos CSR crate，先验证静态资源、API 类型、SSE 连接/断连和错误显示；框架版本在此阶段锁定。
3. **开发闭环**：逐页迁移项目、聊天、审批、diff/恢复、终端和设置，与服务端事件及持久状态对齐。
4. **连续开发与团队**：完善上下文、Key 健康/预算及 Lead 计划确认，接入 shared/worktree 和成员结果验证。

迁移期间保留现有 Rust 服务的 legacy Web 页面；旧 Node/3080 安装也不在本轮删除。只有新界面完成“打开项目 → 提需求 → 批准修改/命令 → 测试 → 审阅 → 接受或恢复 → 重启后继续”及失败路径验收后，才切换默认入口。不得以 WASM 编译成功或空页面可打开，宣称前端迁移完成。
