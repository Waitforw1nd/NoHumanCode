## 缺陷清单与修复验收

### P1 · A03：模型路由可以取到账户令牌

位置：`src/engine.rs:36`、`src/domain.rs:74`、`src/store.rs`。

模型 Key 与 New API 账号令牌共用 `secrets` 表的文本 ID。路由允许 ID 为 `newapi-account`，`Engine::key` 直接用 route.id 查询，因而读到账户令牌。

复现：在隔离实例绑定假账号令牌 → 新增 ID 为 `newapi-account` 的模型路由（不填模型 Key）→ 调用该路由 `/models`。本机模拟模型接口实际收到账号令牌，返回 HTTP 200。Rust 独立探针也复现。

触发条件：可修改本机配置并已绑定账号；不是未认证的远程访问漏洞。后果是账号级凭据被发送给推理 API，影响可能高于泄露推理 Key。

修复建议：凭据按类型命名空间隔离（provider/account），迁移旧记录，同时拒绝保留路由 ID。验收：保留 ID 被拒绝；任意模型路由都无法读取账号凭据；普通路由和余额查询不回归。

### P1 · A05：更换账号站点会将旧令牌发送到新地址

位置：`src/server.rs:201–217`。

绑定处理先覆盖 `settings.newapi`，再在 token 为空时取旧账号令牌，没有比较旧、新站点与账号身份。界面提示“已绑定时留空可沿用”会鼓励触发这个路径。

复现：站点 A 绑定假令牌 → 改为本机不同端口的站点 B，token 留空。站点 B 实际收到 A 的假账号令牌，绑定返回 HTTP 200；浏览器也确认站点变更可沿用旧令牌。

修复建议：将账号令牌与规范化站点及 user_id 绑定；地址或账号改变时要求显式提供新令牌，不能先发请求再校验。`PUT /settings` 也应遵守相同约束，不能绕过专用绑定入口。验收：更换目的地且令牌为空时，在任何外发请求前失败，旧账号仍可查询。

### P2 · A04：WASM 表资源没有宿主上限

位置：`src/wasm.rs:114–150`、`src/wasm.rs:165–167`。

宿主检查导出的线性 memory 上限并启用 fuel，但 `Store<()>` 未配置资源限制器。funcref 表并不受该线性内存上限约束，模块在实例化阶段即可申请表资源。

复现：有 1 页、最大 1 页线性内存，但声明 1,048,576 个 funcref 表元素且没有 table maximum 的模块被 `validate_module` 接受。此探针只用有限内存，没有尝试耗尽主机。

影响：4 MiB 线性内存限制仍然有效，但不能被描述为整个插件的总内存保证；不可信插件可能申请大量表内存，影响宿主可用性。需安装/运行这样的插件才触发。

修复建议：实例化前配置 Wasmi StoreLimits，限制 memory、table 元素、实例/表数量；校验与执行使用同一限制；限制并发执行与编译输入。验收：过量表、memory.grow/table.grow、无穷循环均被有界拒绝，合法插件继续工作。

### P2 · A01：同一幂等键配不同内容，静默返回旧任务

位置：`src/engine.rs:124–130`。

复现：相同 Idempotency-Key 提交 first，再提交 different；第二次 HTTP 200，ID 与旧运行组相同，新的内容没有执行。正常的“同键同内容”八并发去重通过。

修复建议：持久保存规范化请求摘要；相同键、不同请求返回明确冲突，UI 为每次逻辑提交生成并保留键。当前网页提交尚未发送这个请求头，因此后端提供幂等功能不等于网页网络重试也受到保护。

### P2 · A02：任务创建与幂等记录不是同一事务

位置：`src/engine.rs:189–192`、`src/store.rs:90`。

复现：仅在临时数据库用 SQLite trigger 注入幂等 INSERT 失败。启动方法报错，但 runs/tasks 已提交，留下 queued 运行组；任务未被 launch。

修复建议：任务、成员、幂等记录在同一个 SQLite 事务内提交，成功后才调度。验收：任一步骤写入失败时没有孤立运行组；重试只有一个可运行任务。

### P2 · UI01：移除中间队员后再次新增产生重名

位置：`web/app.js:12–17`。

浏览器复现：添加到 lead、worker-2、worker-3 → 移除 worker-2 → 再添加 → 出现两个 worker-3。填写任务并启动后提示“成员名称必须唯一”，无法正常提交。已有固定成员在继续时的身份保持测试通过。

修复建议：用未占用的序号或独立计数器生成名称，提交前在对应字段提示重复。验收：任意移除/添加序列不会产生默认重名；保留成员身份不变。
