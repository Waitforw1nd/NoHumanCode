# 🍑sh harness：PI-Desktop 参考后的目标修订

核对日期：2026-09-21  
参考项目：[vastsa/PI-Desktop](https://github.com/vastsa/pi-desktop)，以及它公开的[架构说明](https://github.com/vastsa/PI-Desktop/blob/main/docs/spec/02-architecture/01-architecture.md)和[E2E 测试计划](https://github.com/vastsa/PI-Desktop/blob/main/docs/spec/06-delivery/04-e2e-test-plan.md)。

## 参考后的判断

PI-Desktop 的关键价值不是 Electron 这个外壳，而是把产品边界拆成了持久工作区、会话、Agent、权限层和扩展层。它把 UI 保持为非特权投影，把 Rust 主机作为文件、进程、密钥、持久化和审批的权威边界；模型/Agent 循环可以替换；插件可以贡献面板、命令、工具、Skills、MCP 和后台服务。它还把 Agent、Plan、Goal 作为同一会话的工作模式，而不是创建多个互相断裂的产品入口。

🍑sh 不应照搬 Electron、Node sidecar 或 PI 的包格式。当前 Rust 服务已经承担了主机和 Agent 循环，继续引入第二套 Agent 引擎会增加模型状态、审批和故障恢复的重复实现。应吸收的是边界和数据模型：

1. **Project → Session → Agent → Work**：一个项目可以有多个持久会话；会话记录固定项目、模型快照、权限和消息，不把一次 Run 等同于全部产品状态。
2. **UI 是投影**：网页只请求经过服务端校验的操作，不能自行决定工作目录、凭据、权限或恢复范围。
3. **模式是会话状态**：Agent（直接执行）、Plan（只读分析后等待批准）、Goal（长任务验收标准）共享一个身份和上下文。
4. **扩展按贡献类型注册**：工具、Skills、MCP、面板、命令和后台服务必须走同一个注册/权限/审计边界；WASM 只是其中一种受限实现。
5. **E2E 先于功能宣称**：安装、配置、打开项目、发起会话、审批、工具调用、测试、审阅、恢复、重启继续必须成为发布门槛。

## 本轮已经落地的目标修订

- `Run` 增加持久化 `kind` 字段（`chat` / `team`），历史路由不再依赖成员名称是否叫 `chat-session`；旧数据启动时会迁移识别旧对话。
- SQLite schema 从 3 升到 4，运行组保存会话种类；历史列表 API 返回 `kind`，前端按持久类型打开对话或工作台。
- 项目工具继续由 Rust 权威执行：新增受控 `search_files`，命令可按用户授权把单次超时从默认 30 秒提高到最多 600 秒；不把命令权限变成后台服务或无限 shell。
- 变更接口返回备份前内容、当前内容和存在状态，工作台提供查看变更摘要与恢复入口；shell 和外部程序修改仍明确不纳入自动恢复。

这些改动选择了“先建立稳定会话边界，再扩展 UI”的顺序。PI-Desktop 的完整插件市场、Electron 原生窗口、远程控制和 Node pi sidecar 不属于当前第一轮目标；它们会在第二、三轮按需要评估。

## 修订后的三轮计划

### 第一轮：单项目日常开发闭环

完成精确补丁/冲突检查、逐行 diff 与接受/恢复、持久终端和后台进程、按工具审批、项目选择、Markdown/代码展示。验收一条流程：选择项目 → 新建会话 → 读/搜代码 → 申请写入或命令权限 → 修改 → 运行长测试 → 查看 diff → 接受或恢复 → 重启继续。

### 第二轮：持久会话与扩展边界

补充 Plan/Agent 两种会话状态、Goal 验收标准、上下文压缩、项目规则、会话搜索/归档/分支、模型能力/推理强度、Key 健康与成本预算。实现最小 Skills/MCP 注册协议和插件权限清单；所有扩展复用 Rust 权限层和 SQLite 审计。

### 第三轮：异构 Agent Team

主 Agent 根据 Goal 生成可审阅计划，派生有独立上下文的成员；成员使用项目 worktree 或资源锁隔离，支持消息、停止、失败重派和结果回收。团队完成必须有独立测试、变更审阅和可合并成果；不把并发 Key 数量当作团队能力本身。

## 明确反驳两种不合理方向

- **“把全部前端改成 WASM 就等于先进架构”不成立。** PI-Desktop 的关键是权限和持久状态边界，UI 技术只是渲染层选择。当前 Rust + HTML/JS 已能满足本地产品；只有在插件沙箱或复杂编辑器需要时才引入 WASM，避免把迁移成本误当成功能。
- **“再加一层 Node Agent 就能追平”也不成立。** PI-Desktop 选择 Rust host + pi sidecar 是为了复用成熟 Agent 引擎并隔离特权能力；🍑sh 已有 Rust Agent 循环。除非明确采用 pi 的协议和生态，否则增加 sidecar 会造成两套会话、工具、审批和错误语义，先把当前 Rust 会话模型做稳更重要。

## 当前剩余硬缺口

本轮后仍不能宣称完整产品：精确补丁、逐行 diff/接受、持久终端/后台服务、多项目切换、按工具审批、MCP/Skills、Git/worktree、自动 Agent Team 和完整 E2E 仍未全部完成。真实 xpeach 流式算术已通过，真实文件工具任务曾在 150 秒窗口内超时，需要单独排查模型工具调用与上游超时。
