# W3 本机恢复方向限定核收

2026-11-01，项目经理。APPROVED（只读设计交付及后续实验方向）；不是恢复功能验收，也不是 schema 或产品实现授权。

已全文审原报告与补充01，实核 main.rs 的正常实例锁、Store::open 与 Engine::new_recovered/recover 入口，独立读取 Microsoft Object Manager 生命周期、Job Objects、RegCreateKeyEx 和 QPC 官方正文。原报告的命名 Job 不足、创建前登记和 resume 前登记、同代 CAS 等发现保留；W3-R01 的外部签名平台必要条件已由普通本机候选替代。

限定采纳创建前持久 QPC/frequency/uptime，以及封门后可选提高检查点；同机、同安装、同数据域且无克隆/OS或DB回滚的受信部署中，新 Host 只有双计数严格下降、频率相同、整数运算安全及身份/门/代 CAS 全满足，才有候选跨启动证据。QPC 的非递减和跨线程一 tick 模糊有官方依据；双下降的恢复用途是设计推论，支持系统上的实际可用性和模式边界仍须实验。不下降不证明同 boot，也不允许按超时解封。

本机方案不新增 HKLM 写权限、外部平台或硬件签名必需依赖；键缺失仍不是证据。跨启动路径不要求旧内核调用在启动前自行结算，但所有旧请求必须被持久围栏，新启动不能有绕过准入的自动重建者。已登记请求在同一启动期的直接恢复仍须真实进程句柄信号及相应前提；没有该证据不能凭 PID 或名字关闭 unknown。C 已修正实验表：process handle 不能跨 OS 启动保留，新 boot 不冒称等待旧 handle 成功。

后续实现必须明确实际安装/数据域身份和 authority 令牌入口、迁移/回滚策略、请求 owner 与恢复 owner 的分别关联。不能据本设计把所有既有 Store 读写改成单一持锁实例，破坏现有多 Store 事务语义；应先冻结外部运行时启动、清理及解封入口所需的独占与围栏，再评估迁移及其他入口的关系。尚无新 schema 实施授权。

W2 不等待本设计即可继续真实组件窗口。C 第二十六轮设计按此范围结束释放；普通重启/休眠/快速启动、创建交界、权限与路径别名、数值边界及并发 CAS 等仍需正式实现和动态验收。没有在本轮重启系统、写注册表或运行探针，不称完整核心已经完成。
