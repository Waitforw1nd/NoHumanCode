## 主要发现

### 1. 高：应用协调职责集中，兼容逻辑仍进入主执行链

[Engine](../../../NoManCode/rust-app/src/engine.rs)的构造、run_task、perform_tool、工作树、配置、审批和恢复共同依赖同一类型；run_task 同时处理旧依赖映射、凭据并发、Agent 决策、Provider 准入、工具结果与任务持久化。

问题在于一次语义调整需要同时理解多条调用链，而非单纯文件长度。NEXT-19 的同组审批、结果文本、参数脱敏与持久绑定回归进一步说明这些责任相互牵连；它们不证明 Rust 或单进程 Host 路线错误。

建议按用例提取工具调用、任务调度、工作区操作等应用服务，Engine 保留薄入口与装配。验收要求生产路径实际改用服务，服务不反向依赖 Engine，权限和状态只有一个权威来源，原事务与取消语义保持。不要先拆大量 crate、引入微服务或重建第二套调度器。NEXT-19 正在朝工具调用服务方向推进，但尚未通过完整验收。

### 2. 高：新旧领域表达的权威边界没有完全落到执行接口

[Domain](../../../NoManCode/rust-app/src/domain.rs)同时提供 Task/Run 与 Session/Turn/TurnTask；[Repository](../../../NoManCode/rust-app/src/repository.rs)说明新模型为持久领域事实，但 Engine 仍主要操作旧 Task，随后由 [Store::save_task_tx](../../../NoManCode/rust-app/src/store.rs)核对并同步新旧状态。

同事务更新、身份与状态一致性检查是现有保护，不是应删除的冗余。本轮没有证明数据已漂移。风险在于新逻辑继续通过旧快照写入，使兼容成本不断增长。

建议逐项明确任务状态、消息、工具结果和执行回执的权威命令及写入者，把旧协议映射集中到适配边界；先迁移调用路径和证明历史数据兼容，再讨论删旧存储。持久脱敏展示参数与执行授权摘要应保持明确区分，不能互相替代。

### 3. 高（交付）：正式界面和默认组合距离产品目标仍有实质差距

[正式 UI App](../../../NoManCode/rust-app/crates/ui/src/lib.rs)只渲染标题、技术说明和会话类型；Host 仍提供旧 HTML/JS fallback。不能说项目完全没有界面，也不能把 WASM 编译通过当作正式 Desktop 已可用。

[PluginHost](../../../NoManCode/rust-app/src/plugin_host.rs)明确仅执行 builtin，拒绝 wasm/process runtime；这不否认单独 run_wasm 工具的存在，但后者不能证明通用 WASM 插件加载与生命周期已交付。生产装配已覆盖 files/shell/Agent/Provider 等真实能力，仍不足以证明项目书的完整默认组合可替换、可撤销。

建议把默认能力逐项映射到生产装配、公开入口、禁用/恢复行为和验收证据。Desktop 以同一 Host 的项目选择、聊天、审批、Diff、恢复、重连为交付链，不另建事实模型。第三方运行面按明确场景推进，不作为每个当前用例的无限前置。

### 4. 高（验收可信度）：失败能阻断，但诊断未必足以定位

NEXT-19 的 W08 与 N13 都在 ready 观察阶段超时。[C 只读诊断](../../员工C/提交报告/第二十轮/NEXT-19工作树前置超时只读诊断.md)指出：W08 监听通知不能证明请求进入 handler；N13 在 caller 提前返回时，探针持有的 sender 仍可能让 ready 等待持续到超时。原 N13 现场不可可靠归属。

Git 单命令超时与整体 ready 窗口存在可能的预算不匹配，但没有实际时序证明其是这次根因。不能将两故障自动合并，也不能默认归因机器负载或通过增大 timeout 消除问题。

建议先补每 case 的有界阶段观测、caller/ready 联合观察与现场保全，再按证据修复。保留原时限、并发和断言；区分产品故障、夹具错误和观测不足。大量通过测试有价值，但不足以证明发布可靠性。

### 5. 中高：阶段完成标准需要收敛，管理记录需要减负

项目书本身已把单 Agent CLI 与 Desktop/后续 Team、MCP、Skills 等分阶段，方向合理。执行上的风险是基础设施切片和兼容补充持续扩展，却没有完成阶段一默认组合与分发验收。

任务板顶部仍写 C 只读诊断待核收，而 C 报告已经存在；多个旧“现行”段并存。不能据此认定代码错误，但足以说明维护同一状态的多个副本容易滞后。

建议每阶段只保留一张可验收交付清单；任务板维护唯一当前状态，身份与进度链接事实来源，原报告/日志按轮次保留。本轮只作必要记录，不删除历史或顺手重写协作制度。
