在自己的环境中定位 PowerShell：

```powershell
Get-Command pwsh
pwsh --version
```

若 PATH 找不到 pwsh，检查本机安装并配置 PATH，不把 Windows PowerShell 5.1 重命名成 pwsh 冒充验证。项目检查从 Rust 目录执行；build.ps1 发现 MSVC/SDK 后设置进程环境，缺依赖时明确报错。它可继承开发者终端的 `VCToolsInstallDir` / `WindowsSdkDir`，不依赖原机器安装目录。

## 最小只读接手检查

```powershell
# 从包含根 AGENTS.md 的仓库根开始
git rev-parse HEAD
git status --short
Set-Location -LiteralPath './NoManCode/rust-app'
rustup show active-toolchain
rustc --version
cargo --version
rustup target list --installed
cargo metadata --offline --locked --no-deps --format-version 1
```

metadata 用于确认 workspace 和依赖路径，不能替代编译或功能测试。需要写简短结果时提取 workspace_root、target_directory 与 package 路径即可，无需把全部 JSON 贴进聊天。

## 实现阶段或 review 需要的检查

在 Rust 工作目录按任务需要运行：

```powershell
pwsh -NoProfile -File .\build.ps1 -Action check
pwsh -NoProfile -File .\build.ps1 -Action fmt
pwsh -NoProfile -File .\build.ps1 -Action test
pwsh -NoProfile -File .\build.ps1 -Action clippy
pwsh -NoProfile -File .\build.ps1 -Action wasm-check
```

必须检查实际退出码，保留日志与当前源码清单。`fmt` 是检查模式；不要全仓格式化覆盖并行员工内容。不要裸调用 build.ps1：默认 Action 是 build，会做发布构建并复制 EXE；只有确实需要该交付时才执行。付费 live 默认忽略，需按用户已有授权单独处理。

已知测试入口：session_turns（B 连续回合），http_contract（C HTTP/SSE），runtime、final_acceptance、assessment_adversarial 与模块内测试；live 为付费外部调用。各测试文件位置见项目地图。

## 当前基线与隔离注意

- 有效交付包括 HEAD 之外的工作区修复与物理迁移。旧路径显示 D、新 NoManCode/niuma 显示未跟踪，属于尚未提交的目录变化；不要 reset/clean 或恢复旧路径覆盖新目录。
- 只检出 HEAD 的新工作树不包含当前有效修复；若做隔离复验，应明确带入当前有效源码并记录哈希，不能宣称一个裸 HEAD 工作树就是最新基线。
- 同时构建可能争用 target、EXE 或测试端口。隔离复验使用自己管理的输出目录和临时数据库；不要结束其他人的进程。若采用 CARGO_TARGET_DIR，只用于明确理解产物路径的检查；发布 build.ps1 当前仍从自身 target/release 复制 EXE，不能假设会跟随自定义路径。
- NoManCode/bin 当前为空，本轮未生成或发布新 EXE。不要把启动脚本存在当成实例已经启动；常规验证使用本机 mock 和临时库。
- 旧 Node 兼容入口使用 `DSH_RUNTIME_ROOT` 指定外部 Harness，`DSH_HOME` 指定数据目录；相对值以 `NoManCode/` 为基准，未指定数据目录时使用 `NoManCode/data/`。Node 由 PATH / `NODE_EXE` 发现。当前源码未携带 node_modules 或 data/skills，路径整理不会补齐依赖或复制旧凭据。
- 不读取或打印真实 Key；本文件不含凭据。现有 .gitignore 会忽略 target、bin、node_modules、data-rust、workspace 等生成/运行目录，业务源码仍可跟踪。
