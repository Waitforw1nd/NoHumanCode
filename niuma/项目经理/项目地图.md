## 3. 两条执行链要分开理解

### 现有 HTTP / UI 链

```text
web/app.js 或 HTTP 客户端
  POST /api/runs
    → server::start（含 JSON、安全与可选 Idempotency-Key 校验）
    → Engine::start / start_idempotent
    → Store::commit_turn_bundle → Repository / SQLite
    → 提交成功后 Engine::launch → run_task
    → Engine::key + 并发控制 → provider::complete
    → delta 回调 Store::event；阶段与终态 Store::save_task
    → SQLite 事件 / Task / Turn 投影

  GET /api/runs/{id}/events 或 /api/sessions/{id}/events
    → cursor 校验；Session 解析为 legacy_run_id
    → open_event_stream → Store::events(id, after)
    → sse_frame → 客户端（读取已持久化事件）

  POST /api/tasks/{id}/resume 或 /cancel
    → Engine::resume / cancel（恢复现有 Task，不是创建一个新 Turn 的 HTTP 命令）
```

HTTP 响应返回并不意味着模型已执行完成；运行在后台，状态与结果通过查询/SSE 观察。SSE 断线不取消后台任务；流内读取或构帧故障发一次安全 error 后结束，不能为传输错误新增业务事件。

已有工具任务的 `run_task` 可从 Provider 回复取出 tool_calls，写入 tool_start/tool_result，并调用 `workspace::execute`；写文件前保存备份供基础恢复。这里的静态 tools/write_scopes/allow_commands 控制不能冒充项目书要求的逐次审批闭环。

### B 已验收、尚未接 HTTP 的连续 Turn 链

```text
应用调用者 / session_turns 测试
  SendChatTurn
    → Engine::send_chat_turn
    → 幂等回放先判定；身份/无工具前缀/上下文/路由预检
    → Store::append_chat_turn（立即事务内重查 latest、完成状态、归属、前序快照）
    → 新 Turn + Task + 新旧投影 + 幂等 + 首事件一起提交
    → 仅新建回执 launch；replayed=true 不再次派发
```

这条链限定已有、单 Agent、无工具历史的 Chat Session；每条新消息创建新 Turn/Task。缺失或空 `tool_calls` 数组允许，非空工具历史明确拒绝，不裁剪或伪造结果。提交后尚未 launch 就中断的任务重启转 interrupted；同 key 回放不自动重派。

`router`的 `/api/sessions/{id}/turns` 现同时挂载 GET 与新 POST；[NEXT-01修订1](../员工C/任务/第二轮/新增Turn-HTTP契约.md) 的 DTO/错误与联合验收已由 C 交付并经 [review 2.1](<../员工C/审查记录/第二轮/员工C review 2.1.md>) 按范围验收，C/D 联合门禁已通过，仍待 Git 基线纳入。UI不得私自复用resume冒充新Turn链。
