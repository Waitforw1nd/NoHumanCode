## 1. 范围与产品流程

shared使用现有Project根和显式Run。worktree由独立管理请求创建，成功后登记新Project，用户另行config CAS、该Project network preview/authorize、显式新Run。创建不启动Provider/Agent、不选择当前Project、不复制源权限/grant/Session/Task/Checkpoint；旧Session新Turn保持原根。注册普通目录不伪称managed worktree，来源关系提供独立查询事实。linked worktree独立检出目录和index，共享objects/refs/common config；不是OS或完整仓库隔离，Shell仍不受files write_scopes限制。

首片只受信任本地、完整SHA-1、非bare/非unborn、已登记根恰为Git工作树根、clean（含staged/unstaged/untracked，忽略文件不复制）的仓库。detached HEAD可；不接受自由ref语法，expected_head必须40位十六进制commit且等观察HEAD。新操作要求干净源，不把旧未提交内容复制。Host生成规范UUID operation_id，branch=codex/workspace/<uuid>（full ref refs/heads/...），target_leaf=nhc-<uuid>。parent必须已存在，leaf任何形式存在均拒绝。用户不能指定branch/leaf/Git选项/force；不支持SHA256、已有branch/目录接管、submodule/LFS/sparse/partial clone、symlink树项。

仅允许显式worktree add产生新branch/管理记录/新目录。无stage/commit/reset/clean/stash/remove/prune/repair/unlock/merge/push/fetch；没有自动删残留或删除.lock。Unknown首片只诊断，保持预约；即使PresentMatching也不登记/释放/重试。人工接纳/解除预约待独立后续契约，当前不承诺未知结果可自动恢复完成。这是本片明确可用性限制，不是成功。

## 2. 公共接口（B定义，C消费）

src/worktree_management.rs公开严格DTO（deny_unknown_fields）：
CreateWorktree { source_project_id:ProjectId, name:String, parent_path:String, expected_config_revision:u64, expected_head:String, idempotency_key:String }。
Engine::create_project_worktree(self:&Arc<Self>, request:CreateWorktree) async -> anyhow::Result<WorktreeReceipt>；
Engine::worktree_receipt(&self, source:&ProjectId, operation_id:&str) -> anyhow::Result<WorktreeReceipt>；
Engine::lookup_project_worktree(&self, source:&ProjectId, key:&str) -> anyhow::Result<WorktreeReceipt>；
Engine::inspect_project_worktree(&self, source:&ProjectId, operation_id:&str) async -> anyhow::Result<WorktreeInspection>。

Receipt固定schema_version=1；operation_id:String（canonical UUID）、source_project_id、name、parent_path（原规范输入）、target_path（规范实际）、branch（短名）、expected_config_revision、expected_head（小写40hex）、request_digest（SHA256）、revision:u64、state:Claimed/Succeeded/Rejected/Unknown（snake_case）、project_id:Option<ProjectId>、cause:Option<WorktreeCause>、created_at/updated_at:i64（既有时间单位）。succeeded iff project_id非空且不同源，succeeded/claimed cause为空；rejected/unknown cause必须安全枚举，不返回原stderr/config/token。运行状态来源是持久receipt，不用HTTP成功或目录存在代替。重放不修改revision/时间。

WorktreeError稳定枚举：Invalid/NotFound/RevisionConflict/IdempotencyConflict/Busy/RootChanged/Conflict/Unsupported/Unavailable/Corrupt；cause可用同类安全诊断加ProcessOutcomeUnknown/RegistrationOutcomeUnknown/Interrupted。B/C对最终枚举拼写在源码前消息确认，语义不变的拼写记录执行登记，不自由增加隐式重试。Inspection { receipt, observation }，观测包含operation_id、observed_at、state:AbsentObserved/PresentMatching/Partial/Conflicting/IdentityChanged/Unavailable、reason_codes安全枚举、observed_head/observed_branch可选；不覆写receipt状态或授执行权。

POST /api/projects/{source}/worktrees：严格body仅name,parent_path,expected_config_revision,expected_head；key用Idempotency-Key。
GET /api/projects/{source}/worktrees/{op}：读取持久receipt。
POST /api/projects/{source}/worktrees/lookup：严格body仅idempotency_key，只读。
POST /api/projects/{source}/worktrees/{op}/inspect：严格{}，只观测。
全部token/Host/Origin/sec-fetch-site保护；操作不属source则NotFound，lookup不能跨source泄漏。create 200仅succeeded、202仅claimed/unknown、409 rejected；前置无claim Invalid400、NotFound404、冲突/Busy409、Unsupported422、Unavailable503、Corrupt500。读正常200可任意持久state。不给客户端retryable=true。

CLI project worktree create --source-project --name --parent --expected-config-revision --expected-head --key；status --source-project (--id|--key恰一)；inspect --source-project --id。CLI只认证HTTP及输入/输出校验，不本地DB/Git/创建目录。create完整回执且succeeded退出0，claimed/unknown/rejected非零；发送后超时、畸形/截断/不一致回执、打印失败均operation_result_unknown，提示按原key查询，不自动poll或重发。lookup/inspect虽POST仍只读，失败不能宣称新副作用。严格重复/未知字段、范围/UUID/OID/branch/目标关系及state/project/cause验证，旧Project DTO/错误/CLI保持。

## 3. D的Git组件与信任边界

D新src/git_worktree.rs，crate内部API，不触Store：
- probe_project_git(root:&RootIdentity) async -> Result<ProjectGitObservation,GitWorktreeError>：NotGit与RepositorySnapshot区分；权限/超时/坏身份不得当NotGit。
- inspect(source:&RootIdentity) async -> Result<RepositorySnapshot,...>；
- prepare(source:&RootIdentity,parent:&RootIdentity,operation_id:&str,expected_head:&str) async -> Result<PreparedWorktree,...>；
- execute_claimed(plan:ClaimedWorktree) async -> Result<CreatedWorktree,...>；
- diagnose(plan:&PersistedWorktreePlan) async -> Result<WorktreeObservation,...>。
operation用canonical UUID字符串，避免API额外类型依赖。Prepared不可Deserialize，私有字段；提供into_persisted_plan/getter及claimed构造供B在持久claim后使用，外部JSON不能授执行权。PersistedWorktreePlan严格version1、operation_id、source_root/target_parent RootIdentity、repository、expected_head、branch_ref、target_leaf、policy_version1。RepositorySnapshot含git_dir/common_dir RootIdentity、head_oid/head_ref、object_format（首片sha1）、config_digest；提供稳定common_key（物理身份+规范路径摘要，不仅路径）。CreatedWorktree含root/git_dir/common_dir、head_oid、branch_ref。GitWorktreeError区分Invalid/Unsupported/Dirty/Conflict/Unavailable/OutcomeUnknown。可为诊断字段/构造器补充最小必要方法，B/D先消息对齐后登记，不改契约语义。

Git使用可信绝对PATH目录解析的绝对可执行文件，拒绝任一登记Project/目标可写根内git.exe，PATH是Host信任输入。Command args不经shell。净化环境沿现git_diff思路，但不改git_diff、不复用其无界cleanup。固定禁global/system config/attributes、协议/提示/lazy-fetch/replace/外部diff/credentials/fsmonitor；逐项固定禁hooks、auto maintenance/gc、submodule递归、branch auto-track、worktree guessRemote、sparse，core.protectNTFS=true。hooksPath和attributesFile为Host管理的空目录/文件（在Host数据位置或专用操作辅助目录，工程验证全E；不得放Project可写范围），必须实际验证存在性/空内容。辅助物创建亦在claim后，可保留不清理。

显式读取common config及存在的worktree config（--file绝对已核路径 --no-includes --null --list，多值全检查），拒绝include/includeIf、filter.*、promisor/partialClone、objects/info/alternates与http-alternates、所有extensions（首片只sha1标准格式0）、core.worktree/bare=true、config.worktree文件/稀疏设置/submodule设置、core.protectNTFS=false；未支持repositoryFormatVersion拒绝。base树有120000/160000拒绝，ls-tree/config输出有界16MiB，超界拒绝。本地.gitattributes允许普通文本属性但filter外部程序配置完全拒绝。配置字节存在性摘要和所有目录身份前后复核；任意未知外部执行配置能力需保守拒绝并报告。恶意外部进程在检查后改config/path不在沙箱保证内，不能把协议禁用说成禁止任意filter联网。

HEAD用固定rev-parse --verify --end-of-options HEAD^{commit}再cat-file校验；执行只传固定OID。命令受控worktree add --no-track -b <短branch> -- <target> <oid>，实际参数次序由D真实fixture验证。不用force/-B。prepare/claim前及spawn前复核clean/HEAD/父/源/common/config身份；成功后核源HEAD/index/文件未被本操作改变、新树.git普通文件/admin/common对应、worktree list --porcelain -z唯一记录、HEAD/branch匹配，目标RootIdentity/重叠策略通过。

只读Git每调用上限10秒；创建及其pipe统一总deadline30秒，额外总cleanup最多5秒（kill+wait、readers abort+await共享预算），有界输出。不声称任意后代全灭。B owned worker覆盖Git+最终落库，caller取消不释放claim/取消worker。spawn后任何非零/超时/超限/后验冲突保守OutcomeUnknown；明确未spawn且无Git副作用才Rejected。Git退出0只是CreatedWorktree，不代表Project登记成功。

## 4. schema14与事务/并发准入

B追加marker git-worktree-operations-v1。严格真实13先verify，再Immediate事务建立规范14表/索引/CHECK/FK，verify→marker/version一次commit；保留旧业务/rowid/密文/plugin receipt/marker字节，13两ID验证不放宽。版本/marker前置与并发开库在事务内重读；14重开校验完整DDL/类型/状态/身份JSON版本/FK，低version提前marker、缺marker、坏DDL/孤儿/非规范状态均拒绝不洗白。旧测试fixture由B按其声称历史版本精准修正，不删旧失败检查。

持久operation至少存完整规范请求+hash（worktree域全局key单列唯一，source纳入hash）、一次解析身份计划、预分配新Project ID、state/revision/时间/cause。claimed/unknown按common_key至多一条，目标规范路径及同common branch预约唯一；Project reservation(project_id唯一,operation_id FK)覆盖本DB全部同common Project。origin表新Project唯一、operation唯一、source/创建基线/实际Root+admin/common身份，不反推旧Project历史。B可决定规范表名/DDL实现细节，但须报告完整DDL和严格校验；字段不得用忽略冲突/清空旧业务迁移偷省。预约/operation均持久不可只内存锁。

新key流程：只读完整盘点本DB所有Project及root binding；D probe同common成员（source必含）。离线/身份不可证不能当NotGit，拒绝本次创建，明示可用性限制。预检所有现有Project与目标不重叠（源/root/admin/common/目标父链安全），root/parent捕获。
Immediate内先key纯回放/异参冲突，再比较完整Project根绑定清单未变、source config revision、身份快照、HEAD计划、预约唯一性，核成员无queued/running Task、claimed或unknown approval/command、claimed或unknown restore；已cancelled Task仍可能worker在途，不能只看Task状态。持久claimed/revision1及预约commit后才Git副作用，不持DB锁await。预检无claim失败仅返回错误；claim后明确无spawn可持久rejected并释放临时预约；已spawn未知保留预约。两个Store连接同DB竞争靠SQLite，不靠Engine gate。

反向同事务ensure_project_unreserved_tx覆盖commit_turn_in_tx（含bundle/newTurn）、resume_task、ensure_approval新记录/claim_approval、批准/ack、claim_restore、commit_checkpoint。旧幂等只读回放优先；旧绑定/Checkpoint Conflict/恢复封存优先不改。拒绝/取消、finish/result落库、恢复unknown与历史读始终能收尾，不挡已claim事实。普通register_project遇任何claimed/unknown operation拒绝新登记（原key回放可），防盘点后普通注册新sibling漏入；这是明确的暂时全局登记限制。成功内部登记用同一事务helper绕此“自己的reservation”限制，但仍核overlap、默认config/root。

Git成功后一个Immediate事务插Project+默认无权限config/root+origin并将operation succeeded/revision++、释放Project/common运行预约；来源保留，不选当前Project。不能直接嵌调当前register_project自带事务，提取同owner helper且旧行为保留。落库失败/进程崩溃继续claimed，能记录则unknown。startup recover只claimed→unknown、revision++，不Git、不清理、不登记、不释放预约；重复recover不漂移。原key重放先于当前HEAD/clean/revision检查，任何state均零spawn，异参冲突，跨source查NotFound。diagnose纯读不改变状态/预约。

并发保证仅同DB Host管控入口；不同数据库Host、外部Git和任意外部Shell不受SQLite锁。不同Host启动recover可能令旧claim Unknown，旧worker不得以过期revision提交Succeeded/释放预约。不宣传跨机器/OS事务。Unknown可阻塞相关Project新执行及所有新登记，本片保守保留，诊断读仍可用。
