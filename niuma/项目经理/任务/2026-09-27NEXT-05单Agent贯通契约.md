## B：工具会话与领域身份契约

1. 保持 `SendChatTurn` 输入、hash版本与 `ChatTurnReceipt` 返回字段；续聊禁止客户端重新指定route/tools/scopes/commands。新key只允许最新已completed的单Agent单Task Chat且无依赖；failed/cancelled/interrupted等仍走明确的旧resume对账，本片不扩全部生命周期。相同已提交key优先回放，不因后续恢复/插件禁用而再派发。
2. 精确继承完整Route快照、workspace、name/role、tools/write_scopes/allow_commands/max_rounds，创建新Turn与新Task，保持Project/Session/Agent。当前Host工作区也须与原Project/Task同根，路线取钥仍按既有base_url绑定。新增有权限Task必须做 `scope_conflicts`，send/start/resume/restore继续共用gate。
3. 历史仅复制合法且工具组完整闭合的消息；禁止半截/重复/孤立结果、跨组错配、恶意工具结构。新调用id不能与复制前缀重复；旧调用/结果不执行、不新建审批、不复制授权。事务内按实际Session的Turn/Task来源核对受审批调用及结果归属，不能把后继Task的累计消息误认为旧approval归其所有。
4. 在append的立即事务内复核最新前序、状态、单Agent、Route/权限/workspace及候选消息快照。不能只做Engine预检；候选快照比较新增tools/scopes/commands。扫描该Session历史关联Task的未决副作用：pending/approved未finished/claimed/unknown、change prepared/unknown、restore claimed/partial/unknown均阻断新key。denied/cancelled且有明确结果、finished、明确failed change可继续；complete恢复且原Taskcompleted可继续，旧Task写封存不解除。
5. complete恢复后新消息上下文必须明确已有恢复事实，不能让模型把旧write结果当当前磁盘事实；仅加入Host生成的安全恢复提示，不改写历史工具结果或引入用户内容为system指令。提示构造和事务快照比较一致，重复回放不追加第二次提示。无恢复历史的旧无工具行为保持。
6. 新增 `ChatTurnError::UnresolvedEffects`，HTTP映射409 conflict、固定安全消息、retryable=false。保留旧错误语义和旧resume兼容，旧Turn已有后继仍不可resume。无新schema、无隐式reconcile或自动重试unknown。
7. 公共只读接口：`domain::RunContext { run_id: String, project: Project, session: Session, latest_turn: Turn, tasks: Vec<TurnTask> }` 可Serialize；`Store::run_context(&str) -> anyhow::Result<RunContext>` 在同一DB锁/一致快照读实际映射与最新提交顺序。新增 `RunContextError::{NotFound, Unmapped, CorruptState}`：没有Run为NotFound，有Run无领域映射为Unmapped，不猜ID、不补造身份；解码/关系不符为CorruptState。数据库瞬时错误保留source。

## D/B：最小生产 builtin 契约与冻结 API

Host新增 `ResolvedPayload<T> { provider_id: String, effect_id: EffectId, key: InterfaceKey, payload: T }` 及 `PluginHost::resolve_bound<T: Any + Clone>(&self, consumer_id: &str, key: &InterfaceKey) -> Result<ResolvedPayload<T>, HostError>`。按消费者激活快照requires/plan/provider/effect与双方Active检查，真实payload downcast，错误类型明确拒绝；不做全局查找或跨scope回退。

`tool_runtime.rs` 冻结接口：

```rust
pub struct ToolRuntime; // 私有成员，内部同步Mutex，不能公开绕过撤销的registry
pub struct ToolLease;   // 不可Clone，持实际service，execute消耗lease
impl ToolRuntime {
    pub fn builtin() -> anyhow::Result<Self>;
    pub fn definitions(&self, task: &Task) -> anyhow::Result<Vec<Value>>;
    pub fn acquire<A>(&self, task: &Task, name: &str,
        admit: impl FnOnce() -> anyhow::Result<A>) -> anyhow::Result<(ToolLease, A)>;
    pub fn disable_builtin_files(&self) -> anyhow::Result<()>;
    pub fn unload_builtin_files(&self) -> anyhow::Result<()>;
}
impl ToolLease {
    pub(crate) async fn execute(self, task: &Task, args: &Value) -> anyhow::Result<Value>;
}
```

两个 `service` key `tool.read_file@1.0.0`、`tool.write_file@1.0.0` 由 `builtin.files` 注册；`builtin.engine-tools` 声明requires并形成真实激活绑定。payload实际为 `Arc<dyn ToolServiceV1 + Send + Sync>`，definition和execute均来自payload；服务调用现有workspace实现，不持Store/Key，不自行审批。若因Rust可见性需要变更上述签名先向经理报告。

其他list/search/run_command/run_wasm在ToolRuntime中明确兼容分支，经同一definitions/acquire入口，但本片不宣称它们已插件化。禁止被禁用的read/write又从兼容分支回流。权限声明不等于授权，Host固定policy不能由插件改为Allow。

Engine生产构造初始化runtime，Provider定义/调用前验证/最终执行都接同一实例。审批等待期间不得持lease；批准后runtime短锁内复核真实服务与task权限并同步执行admit（B在此claim）。停止与acquire以此锁线性化：停止先胜则零claim/零FS；claim先胜的唯一lease可完成既有结果事务，停止只阻止后续admission，不强杀在途副作用。claim失败无lease。锁内不跨await、不执行FS；锁顺序不得出现Store→runtime反向嵌套。lease不持久化/不恢复，崩溃沿用unknown。

B添加Engine公开 `disable_builtin_files` / `unload_builtin_files` 方法委托runtime，以便验证真实Engine撤销；本片不新增HTTP插件管理面。现有workspace gate、准备before、绑定、cancel、finish事务均保留，`approval_binding`静态definitions仅作权限上限，不代替活动性验证。

## C：CLI 与 HTTP 贯通契约

新增 `GET /api/runs/{id}/context` 调用B接口；RunContextError分别404 not_found、409 conflict、500 internal固定脱敏消息，DB瞬时失败保持现行映射。新增UnresolvedEffects映射，其他HTTP结构与防护保持。

命令冻结：`project list`；`run start --title T --route R --message M --key K [--tools] [--scope S ...] [--allow-commands]`；`run list/status/context`；`session status/turns`；`session send ID --agent A --after-turn T --message M --key K`；`run events`/`session events ID --after N [--limit N]`；`task resume ID --message M`、`task cancel/changes/restore ID`；既有审批四命令保持。create固定chat单Task无依赖，工具/命令默认关闭，scope无默认星号；scope或allow-commands要求tools，不自动扩大权限。

run start成功返回安全Run投影及run_id，用户用context发现身份；避免POST成功后context失败导致误报未创建。CLI不猜最新前序、不自动换key重发，不把resume称新Turn。status白名单输出必要任务状态/结果，不无条件透传messages/内部before等；当前workspace与route可用于用户理解调用目标。参数2、业务/连接失败1、成功0。

固定loopback/no_proxy/no_redirect/短超时/1MiB普通响应上限保留；所有写请求bootstrap取token，不落盘/不回显，无自动POST重试。start/send显式非秘密key，同key手动重试沿服务器幂等；其他写动作结果不明提供固定安全说明与查询入口，不能伪装确定失败/成功。restore的partial/unknown/conflict HTTP错误必须保留经typed校验的receipt/status/restored事实并exit1，不丢掉逐路径结果。

SSE独立client无4秒总超时但有连接/停滞/单帧缓存上限；解析chunk分割UTF-8、CRLF、注释、多行data与多帧，id严格0..i64::MAX；JSON模式NDJSON。合法事件完整输出flush后才推进cursor，流内error/损坏帧/EOF exit1并给最后cursor；limit完成exit0，Ctrl+C仅退出观察不cancel任务。首片手动用--after重连，不自动重发写请求。禁止把bootstrap token、Key或内部密文输出。
