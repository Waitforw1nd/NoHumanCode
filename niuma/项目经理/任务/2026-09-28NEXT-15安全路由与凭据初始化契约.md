## 2. 用户流程

1. 在明确的数据目录和工作目录启动peachsh。新库未传--legacy-data时，仅创建本机初始Settings（routes空、newapi空、max_concurrency=3），不扫描旧目录、不读环境凭据、不选Provider、不联网。启动帮助说明：旧数据导入必须显式--legacy-data；已有数据库不清空、不重导入。
2. `peachsh --port PORT --json host config get`读取Host revision和路由的公开视图。新库revision=0；不能将旧库首次迁移revision=0解释为没有旧配置。
3. `host route set ID --expected-revision N --name NAME --base-url URL --model MODEL --max-tokens N --parallel-limit N --key OPKEY`，必须且只能指定`--credential-prompt`、`--credential-stdin`、`--keep-credential`之一。参数只包含公开配置/幂等key，不提供--api-key或--token值参数。
4. prompt从真实控制台无回显读取；stdin仅接受重定向管道，拒绝TTY，读取有界单行UTF-8，去掉至多一个末尾LF/CRLF，其他空白/多行/控制字符不静默trim。两者统一1..=4095字节、非空、可用于Bearer且禁止空白/控制字符。取消/EOF/编码或长度错误时无PUT。示例只用占位符与隐藏输入，不把真实密钥拼成shell命令。
5. 保存回执明确：仅本地配置，未授权联网、未验证Provider可用。`host config operation --key OPKEY`只读查询原回执；`host config get`读当前状态。原回执可能早于当前配置。
6. 依现有project create/config get/config set/select显式登记同一工作目录，allowed_route_ids/default_route_id引用该路由。配置Project权限与选中Project是独立动作；初始化不自动允许tools/write/command，不自动创建/换绑Project。
7. Completion前先显式设置该Project预算，再network preview及按实际config_revision/credential_revision/binding/purposes授权。Models/Completion目的仍独立；route check包含Completion并受预算，不在保存配置时偷偷调用。
8. 完成一次本地mock的显式请求及Host重启，重新bootstrap认证token，确认配置与receipt保持、授权语义不变且不重复Provider调用。本片正式测试仅本地mock，无付费live。

## 3. 公共DTO与HTTP冻结

公共类型放新模块`host_configuration`，B唯一写入并由lib导出；具体Rust实现可选内部helper，但下面wire名字/字段/语义不得各层自造。

- `RouteInput`：name、base_url、model、max_tokens、parallel_limit；全部必填，无key_env，ID来自URL/命令。数值使用整数并复用现有范围（16..=65536，1..=8），拒绝null/浮点/负数/越界；ID沿domain::valid_name并拒绝newapi-account。name/model使用已有安全元数据校验并限500字节。URL先provider_transport::validate_target规范化；新入口只允许HTTPS或literal loopback IP上的HTTP，不以localhost/DNS推断loopback，不查询DNS。拒绝userinfo/query/fragment、编码斜线与点段，额外安全元数据检查拒绝已知敏感文本。此限制不追溯改写旧路由。
- `CredentialUpdate`：严格tagged union `{mode:keep}`或`{mode:replace,value:SECRET}`。replace必须非空有效；keep不接受value/null。请求类型不derive Debug/Serialize或用明确redacted实现；响应绝不包含此类型。CLI受控构造请求，不用通用调试输出。
- `ConfigureHostRoute`：expected_revision、route:RouteInput、credential:CredentialUpdate；route_id及idempotency_key由入口传到应用层；同一验证同时用于Store公开入口，不能只靠HTTP。
- `HostConfigSnapshot`：revision、routes:[RouteConfigView]。视图字段id/name/base_url/model/max_tokens/parallel_limit/key_env及credential_source（stored/environment/legacy/missing/unavailable）。key_env只为已有兼容配置展示安全的变量名，永不返回值。present来源表示本地可用，不等于Provider验证。DPAPI/环境读取异常不可伪作missing；source unavailable，输出固定安全说明。无账户令牌、完整Settings或任意SQL/blob透出。
- `RouteConfigReceipt`：operation_id（Host UUID）、route_id、revision（提交后的Host revision）、route（提交时RouteConfigView）、changed:bool、committed_at。receipt不含输入key、秘密、hash或ciphertext。
- `RouteConfigResult`：receipt、replayed:bool。lookup结果同此形状且replayed=true；查询不产生新配置写入。

| 方法/路径 | 行为 |
|---|---|
| GET /api/host/config | authenticated当前快照，200 |
| PUT /api/host/routes/{id} | 严格ConfigureHostRoute + 必填唯一Idempotency-Key，首次/回放均200，replayed区分 |
| POST /api/host/config/lookup | 严格`{key:OPKEY}`只读查询原持久回执，200；未知key404，不创建记录 |

新路径全部需Host token，包括GET；沿现有Host/Origin/sec-fetch-site限制。bootstrap保持本机兼容，token是现有本机请求边界，不冒称OS用户隔离。strict JSON包含所有嵌套重复键/未知字段/错误类型；复用StrictObject，body上限1MiB。错误统一`{error:{code,message,retryable:false}}`，message固定安全文本。400 host_config_invalid、403 forbidden、404 host_config_not_found、409 host_config_revision_conflict/host_config_idempotency_conflict/host_config_busy/host_config_credential_required、500 host_config_corrupt/host_config_unavailable/host_config_internal；413/415保留HTTP含义、code host_config_invalid。明确本片错误不带Provider call或dispatch_state，因为配置从不发Provider。

## 4. Host事务、revision与幂等

必要迁移schema15→16，两张受约束sidecar：host_config_state（单例id=1，revision非负且<=i64::MAX）；host_config_requests（全Host路由配置key唯一，operation_id唯一，route_id、expected/result_revision、DPAPI封装的request_fingerprint_blob、非秘密receipt JSON、committed_at）。由B冻结具体DDL列/约束验证；不复制秘密进入JSON，不共享预算/网络/运行的key命名空间。receipt与列身份/revision/时间逐值校验，坏密文/坏结构fail closed；不能用列名齐全代替约束验证。

迁移只新增表/marker/单例revision=0，不解密或改写旧config/secrets/network/budget/Task行、rowid、blob与事件。空库也走同一迁移。双Store open、损坏DDL/marker/关系、失败回滚须有证据。不得为兼容把旧数据库重建或裁剪。旧schema精确fixture只按授权新增空表/marker/版本，保留原断言目标。

新命令在Engine gate内复用已有busy与所有network slot空闲约束；先查原key回放，合法回放不被后续busy/CAS挡住。新写再检查busy、CAS、当前配置/凭据，单Immediate事务完成Settings单路由合并、secret写入、revision、所有受影响Subject/grant、请求回执。禁止读全量Settings后释放锁再覆盖；其它route、workspace、concurrency、account及Project/预算原样保全。

replace统一写secrets的route::ID，新增路由key_env=None；旧路由replace也清除该路由key_env，防环境覆盖新DPAPI值；旧raw ID密文保留兼容历史但不作为新输出。keep仅用于已有路由且当前凭据可用；保留其env/legacy来源，不改变key_env；更换规范化API base URL必须replace，禁止把旧Key静默送到新地址。模型/名称等更新可keep但照常重新检查网络绑定。

请求指纹定义：固定version的规范请求（route_id、expected_revision、全部规范RouteInput、keep/replace，replace包含按长度编码的原始秘密字节）计算SHA256，**只将摘要经DPAPI seal后的blob持久化**；禁止把裸秘密摘要放数据库、回执、日志或错误作为可枚举匹配器。回放先解封摘要比较，再返回原receipt；不同route/参数/动作/secret/expected_revision复用key一律冲突且无写。DPAPI随机ciphertext不当作语义相等判断。公开receipt可独立lookup，不需要重新输入秘密。

同key同参数并发只形成一个操作；不同key同expected_revision真实变更只有一个成功；同配置同凭据新key为changed=false，保存新receipt而revision不增（因此两个无变化操作可并存）。真实变化revision checked+1，一次原子操作只加1。revision是Host本地配置/凭据写入版本，不是Project配置版本、network Subject版本或环境变量版本。

旧PUT settings、账户绑定及Host生产配置/secret写入口亦必须在自身原子事务内维护Host revision，避免旧界面绕过新CAS；不为旧接口伪造幂等receipt。Store低层save_settings/put_secret的受支持写入也须使revision失效；初始化顺序须明确首初始Settings不造成不可解释重复revision。统一封装事务helper，不改旧业务/数据意义。原网络refresh_subject逻辑必须在同事务复用，不另写第二套grant事实。

## 5. 配置、授权、预算与恢复关系

配置成功不产生NetworkAuthorization/NetworkCall/BudgetCall，不自动Project授权/选择/预算，不进入Provider。新路由还须被显式加入Project allowed列表。路由配置是Host范围，一个route被多个Project使用时其受影响Subject均按旧规则stale；不修改旧Task网络绑定、permission snapshot、路由快照或grant。Name等不影响绑定的无关变化可保留授权，不能把Host revision变化直接等同所有网络授权撤销。

已有env/legacy来源选择与network snapshot规则继续：环境外部改变不自动增加Host revision，但network preflight/claim仍必须检测与授权绑定不一致，先preview并重新确认；不得借新配置receipt绕过。保持原配置恢复旧Task仍使用原绑定，unknown不自动重试。预算原预约/usage/overrun/unknown和Project独立性不变，配置不清零或释放。

保存配置不宣称冻结操作系统环境、隔离同用户恶意进程或保护任意未知秘密嵌入公开元数据。DPAPI仅当前Windows用户边界，内存清零为尽力，不能保证OS/依赖没有副本。输出验证既做结构白名单/已知敏感文本，也在本次replace客户端校验任何响应不包含本次secret或bootstrap token；不可依赖scrub检测任意未知秘密。

## 6. 失败、未知与诊断

- 输入/校验/DPAPI加密/CAS/busy失败：无配置/secret/revision/grant/receipt部分提交，固定安全错误；不打印底层serde/SQLite/DPAPI错误中的请求内容。
- commit前真进程终止：恢复为旧配置、无receipt；commit后响应前终止：新配置/secret/revision/receipt全在。配置没有外部副作用，不能添加自动重试或人为unknown解锁表。
- CLI bootstrap/本地输入失败发生在PUT前，可报明确未发送；PUT已交给transport后断线/超时/重定向/超大体/截断/非法JSON/错身份/不可信成功响应，以及stdout失败，均operation_result_unknown、exit1、retryable=false。不根据连接错误推断Host没提交；retry never/no_proxy/no_redirect继承。
- 首先用operation --key查原receipt，再config get当前值；可显式原key原参数重放，不自动重发/换key。lookup404仅表示查询快照未见记录，不证明另一原请求永不提交；原请求仍在途时保持未知，不以404自动新key。
- DPAPI无法解密/历史状态损坏时固定unavailable/corrupt；不得当成无凭据、自动清空、覆盖或复用任意Key。秘密输入取消不得保存半条路由。

## 冻结补充01：实现签名与初始版本

同日经理自审补充，属于v1.0完整读取范围。Engine公开签名为`host_config(&self) -> Result<HostConfigSnapshot, HostConfigError>`、`host_config_operation(&self, key: &str) -> Result<RouteConfigResult, HostConfigError>`、`async configure_host_route(&self, route_id: &str, request: ConfigureHostRoute, key: &str) -> Result<RouteConfigResult, HostConfigError>`。HostConfigError枚举对应第3节各host_config错误，纯固定安全文案；C不根据anyhow字符串猜错误。Store对应逻辑由B提供，并与Engine一致验证，不绕gate暴露外部写端点。`store::fresh_settings(store: &Store, workspace: &Path) -> anyhow::Result<Settings>`仅用于不存在settings时安全初始创建。

schema16初始化单例revision=0；fresh_settings只在settings不存在且没有配置历史时原子保存初始空配置，保持0。已存在settings时返回或拒绝而不覆盖；运行时其它真实配置/凭据写必须递增。显式legacy初次导入可因实际导入写有大于0的revision，不能依赖固定0；其旧导入行为不承诺跨所有旧文件原子化，本片安全默认路径不读取这些文件。低层helper先校验状态，不能允许重复fresh_settings绕过revision。

D credential_input真正文件形成前B不能添加导致缺模块的lib导出后宣称可编译；先固定公共Host DTO，D独立完成真实文件，经理核冻结后串行整合，B再唯一导出。严禁临时假实现作为C联测证据。
