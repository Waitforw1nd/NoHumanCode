## 1. 目标与真实保证

用户可以显式为Project设置累计token准入额度，查看已结算/在途/未知占用及逐call诊断。每个模型Completion（包括route check的无Task completion、每轮Agent工具调用后的下一次completion）在Provider副作用之前由Store同事务预约；并发调用不能各自花同一份可用额度。

单位为Provider报告的整数total_tokens=prompt_tokens+completion_tokens，不是货币、真实账单或Tokenizer估算。本版本只保证Host准入账本的额度检查，不能保证兼容Provider的实际token消耗不超过额度。固定每次预约R不是Provider真实上界，max_tokens只限制请求输出参数；Provider实际返回超预约/超限必须如实记账并阻后续调用，禁止截断数字或宣称硬token/美元预算。Models/Balance不产生completion token预算，但继续受网络授权约束。Shell内部网络也不在此账本或OS沙箱保证内。

## 2. 配置、范围、兼容

新增独立project budget sidecar及schema15，不改ProjectConfig、其permission digest、Task旧JSON或CallReceipt字段，不让预算修订使旧grant自动换绑。scope为稳定ProjectId，所有route/Session/Task共享一个累计额度；不同Project（含linked worktree Project）独立，没有共享账号总预算或自动继承。

公开BudgetConfig：limit_tokens、per_call_reservation_tokens两个u64整数；limit允许0..=1_000_000_000_000，R允许1..=1_000_000_000。不用浮点，不接受负数/字符串/小数/溢出/未知或重复字段。R>limit合法但没有可准入调用，诊断显示不足。累计整数/求和用checked算术并控制SQLite有符号边界，任何不可表示状态fail closed为corrupt，不能wrap/saturate掩盖账目。

BudgetConfigSnapshot：project_id、revision、config:Option<BudgetConfig>。未配置revision0/config:null，明确unconfigured/unmanaged，不伪称受保护。首次set expected_revision0创建revision1；后续set CAS revision并保留所有账项和占用。设置请求含project_id、expected_revision、idempotency_key、config；相同key同规范化参数先回放原BudgetMutationResult，即使当前revision已前进；同key异参/跨project冲突。全budget操作key唯一，沿用现有key长度/字符限制。无disable/delete/reset/周期清零/人工settle/release命令；提高limit或修改R不清除unknown/overrun，不回写已claim快照。limit可降到已占用之下，仅阻后续；已claim不取消。

初次配置只覆盖生效后的claim，不倒填历史调用为0。初次配置与本Project既有claimed completion须同事务互斥：若有任意既有claimed completion返回budget_busy，待其完成或恢复unknown再由用户显式set；配置写成功后任何新completion均必须预算预约。历史finished/unknown缺预算账项标unmanaged，不纳入新scope，不伪造用量。未配置时继续旧行为；旧Task/Session/grant不换绑、不复活封存Task。后续配置修订不是新预算周期。

## 3. 原子准入与持久模型

Store.network_admit已有Immediate事务：检查现行Project/Task身份、grant/route绑定及现有互斥，然后查预算；已配置时先拒unknown/overrun/corrupt，再检查spent + held + R <= current limit，通过则在同事务插入network_calls claimed和唯一call_id预算账项。预算账项保存ProjectId、budget revision、R快照、call_id、task_id可选、route身份（安全ID），不能持密钥、prompt或响应全文。tx commit后才创建/交付permit；budget拒绝不得新增network claim、预算账项或Provider请求。

held为claimed与unknown/usage_missing/usage_invalid账项的R总和，spent为settled/overrun已确认total总和。status与诊断在同一DB读快照内计算，不依赖Engine内存信号量或task.usage，也不复制持久aggregate而引入两份真相。可用值对外max(0,limit-spent-held)，同时单列超额和阻断原因；内部仍checked算术。

schema15在Store启动与Repository两侧严格验证DDL/PK/FK/UNIQUE/CHECK、JSON与列身份、版本marker；迁移14非空/密文/rowid/所有旧表字节值保持，事务失败完整回滚。预算账项与network_calls/project关联，配置请求receipt保留严格JSON及请求指纹。设计的具体DDL由B实现并报告，不允许仅按同名表/列就认兼容。旧fixture如需新增空表预期，只改精确schema预期并保留旧行为断言。

## 4. 结算、重复与未知

预算账项状态冻结为claimed、settled、not_sent、usage_missing、usage_invalid、unknown、overrun；后六者是终态。每call只能结算一次，存稳定终态指纹；同call同语义回执重复是纯回放，不重复扣/退；不同usage/结论重复为budget_conflict且原终态不变。完成时间是第一次持久值，不把重试时now作为冲突原因。这个幂等是内部结算语义，绝不开放客户端伪造Provider用量的HTTP写接口。

只有provider.complete返回Ok且usage严格有效时：原R释放，实际total计入spent；total<=R为settled，total>R为overrun，照实存actual并永久标此Project overrun阻新completion。总spent超过limit也阻后续，不回滚已经发生调用。网络success与用量unknown为独立维度：成功但missing/invalid仍可返回模型消息和合法工具处理，下一completion不得准入；HTTP/CLI诊断必须显出usage状态，不能把网络finished等同已知零消耗。

严格usage：prompt_tokens/completion_tokens/total_tokens均非负整数且<=i64::MAX，checked(prompt+completion)==total；0/0/0有效。null/未提供是Missing；非null结构错误/缺字段/负数/小数/字符串/溢出/不一致为Invalid。未知可选details不计费也不泄漏。重复usage按三整数规范值完全相同接受一次；冲突永久锁存Invalid，后续有效块不能洗掉；partial不能与后块拼造有效三元组。D保持complete原tuple及TransportError签名，提供独立typed classifier；Decoder输出只传规范安全值/固定invalid标记，禁止保留原始响应作为诊断。

TransportError::Invalid确证NotSent时原子标not_sent/释放R，不能把一般HTTP失败/超时/解析错误/取消算not_sent。任何已发送错误、无有效成功用量、caller取消、流截断/finish length/content_filter等保守unknown且保留R；本片不扩大API挽救失败响应中的部分usage。HTTP非2xx虽网络finished，预算仍unknown。finish_network与预算终态同一Immediate事务，不能先保存network finished后独立改账。持久失败返回unknown；DB未提交仍claimed并占用，重启归unknown。

recover_calls_tx同事务将network claimed和预算claimed转unknown，保留R，禁止自动重试/释放/重新预算/创建新call；终态不变。已有owned worker不被预算配置变化撤回。本片不能用drop Arc冒充崩溃，要process kill+wait或明确runtime终止再开新Host。

C新增认证HTTP：GET/PUT /api/projects/{id}/budget（读配置/写配置），GET /api/projects/{id}/budget/status，GET /api/projects/{id}/budget/calls/{call}。PUT严格body仅expected_revision、idempotency_key、config，ProjectId取path；Body限制沿现有最小安全策略，拒重复/未知字段、无token、不正确Content-Type和超大体。查询不得写DB/发Provider。错误安全envelope code + dispatch_state + call id必要事实，原network路径预算准入失败同步network错误枚举/CLI白名单，不能走泛化内部错误。

CLI：project budget config get --id P；project budget config set --id P --expected-revision N --limit-tokens L --per-call-reservation-tokens R --key K；project budget status --id P；project budget call --id P --call-id C。沿既有--json/安全stdout/错误exit1；GET预算状态成功exit0，即使blocked也明确展示诊断。PUT断线/畸形响应/输出失败视写入结果未知，不自动重发；用户可以原key显式重放配置或GET核查。Human输出明确token准入不是真实费用硬上限、unconfigured未启用、unknown/overrun无自动解除；JSON严格校验ID/金额范围/状态组合。CLI只能调用Host，不直读SQLite。

## 补充02：预算PUT抽取错误（2026-09-28）
