## 1. 来源、基线与边界

用户要求整项目迁移后继续下一轮。活动仓库及新树在迁移后的同一磁盘，旧仓库与旧树保留。本文路径以仓库根为准，不依赖盘符。读取 NEXT-07 完成交接、联合验收、整合记录及实际 Project/Settings/Task/Session/Workspace/审批代码后制定本片。

只读输入 HEAD `b9997c8b60c35b14005e88a318d171527df92d28`，NoManCode tree `0f01cd6c1621a16cef842a583028b91cc80f4e12`，Rust tree `f303e198698c8b68f11f937b6ec405fe8db6a70a`，开始时 status/index 空。NEXT-07 的 396/0/1 及五门禁全 0 是已有证据，本轮尚未运行产品测试。开发完整基线在冻结后的派发记录登记，不能拿本草案 SHA 代替。

目标链：登记本机已有项目 A/B → 配置各自权限上限和默认路由 → 分别明确网络授权 → 选择新任务默认项目 → 明确项目创建 Task → 切 B 后仍可按 A 的固有身份继续 A 的会话、审批和恢复。

## 2. 领域与权限

Project 原有 id/name/root_path/timestamps 保留。新增项目配置和 Task 绑定 sidecar，不改旧 Task JSON、approval-binding-v2、Checkpoint 密文/manifest 或 NEXT-07 历史 digest。

项目根和名称本片创建后不可变。复用明确匹配的历史 Project ID；路径冲突、历史重复或根无法确认必须拒绝，不能猜一个 ID。同一真实目录和嵌套项目根都拒绝重复登记，第一片不支持重叠根。RootIdentity 捕获和验证由 D 的唯一模块实现。

ProjectConfig 是权限上限，不只是 UI 默认值：

| 字段 | 语义 |
| --- | --- |
| revision | 正整数，CAS 更新后递增；失败/重复读取不递增 |
| allowed_route_ids | Host routes 的显式允许集合；空集合表示不能开始模型任务 |
| default_route_id | 可空；非空必须在允许集合且 Host route 存在 |
| tools | 工具总上限，默认 false |
| write_scopes | 已有规范的相对目录/文件集合；默认空，无隐式星号 |
| allow_commands | 默认 false；true 还要求 tools=true 和既有逐次命令审批/网络知悉 |

创建只生成 revision=1 的安全空配置。config 更新是整体替换，不做隐式合并；上限必须显式填写，拒绝未知字段、无效 route/scope、越界和不一致组合。write scopes 子集按规范分段包含判断，不能以字符串前缀或任意 glob 代替；原 `*` 只按已冻结全工作区语义。

Task.spec 仍是实际不可变权限快照。新 Task 同事务绑定 project_id、root_identity、project_config_revision、permission_digest、provenance=native_v1。会话后续 Turn 继承前序 Task 的 route/spec 权限；当前配置变宽不扩大旧任务，变窄后若旧快照超出当前上限，新的模型/工具副作用准入拒绝 permission_revoked。当前配置不是实时覆盖 Task.spec 的来源。

选择只修改 Host 默认 project_id 与 selection revision，不保存 Settings.workspace，不触发执行/批准/重试。运行中的 A 不阻止选择 B。权限修改与准入使用同一短 gate + DB 事务：撤权先赢，后续准入拒绝；已经持久 claim 的操作保留在途事实，不伪称撤回。网络 await 不持 gate。命令能力跨项目采用 Host 保守排他，cwd 不构成文件/网络隔离。

Host 共享 Settings 的 routes/Provider 连接、凭据、账号和 max_concurrency；页面明确其 Host 范围。Settings.workspace 仅兼容旧配置读取/首次初始化字段，不再用于运行时项目切换；已有项目后实际修改该字段拒绝 workspace_selection_managed 并指向 project select，不能部分保存其余字段。完整 Settings 回传但 workspace 原值不变必须允许；响应中该字段为原兼容值，不伪装为当前选择。

## 3. 根身份与历史对象

Windows 支持普通本机目录：持久卷标识与目录 file ID，捕获后复核；根及祖先 reparse、无法识别身份、大小写敏感根明确拒绝。不使用 Unicode lowercase 模拟文件系统身份。非 Windows 的测试实现应有明确 dev/inode 语义和平台条件，不能为 Windows 测试返回恒等身份。具体公开 Rust 接口在预审收口后冻结。

每次实时 Workspace 读取、Diff、Checkpoint、resume、新 Turn、审批 claim、write/command/restore 副作用前核 Project→Task sidecar→原根。根丢失、删除重建、改为 junction、ID 不一致都失败；双方 canonicalize 失败不能比较成相同根。切项目不得修改既有 Task 的 workspace/cwd，不能把 A 的恢复落到 B。持久 claim 后才发生的拒绝沿既有已领取/失败/unknown 规则保存真实事实。

这是重新检查路径和目录身份的防护，不是持有目录 handle 的完整文件系统隔离，不保证任意外部进程在校验后更换目录时绝无 TOCTOU。

schema11 不追认历史根身份。无 Task 项目 sidecar 的历史 Task 标 legacy_unbound，保留纯历史查询、旧幂等结果、审批/网络/Checkpoint 元数据和历史 receipt；实时文件读取、创建 Checkpoint、恢复、新 Turn、resume 和新副作用拒绝 project_legacy_unbound。旧 Task 的历史批准不等于新目录授权。本片不提供自动 adopt；继续工作应在明确配置项目中创建新 Task，不能把旧 Checkpoint 应用到新 Task。此兼容收紧包括关闭旧 Task 原本可执行的恢复，须在 UI/错误说明和迁移报告明示，不把旧测试机械改为通过。deny/cancel/停止允许，已持久化 Checkpoint 同 key 的纯历史回放保留。升级启动的后台调度同样不得给无 sidecar 的旧 Task 新准入；沿原 unknown/reconcile 事实停止，不能仅挡 HTTP。

新建项目可显式登记某历史 Project 的原目录，但这只确认当前根，并不自动给其旧 Task 补 sidecar。无领域映射的 legacy Run 保持原 unmapped 语义，不猜 Session。

## 4. 网络项目边界

新 route preview/confirm/admit 的授权主体为 project_id + route_id + 原配置/凭据 revisions 与目标摘要。新版本 digest 使用独立版本，不改历史 v1。A/B 同 route/URL/key 仍须各自确认；A 的 grant 不能让 B 的任务或 models/check 发送。配置保存/选择/登记均零网络授权、零网络调用。

Provider 传输仍使用 NEXT-07 单次 permit、固定目标、无自动重试、持久 call。项目网络命名空间须在 Host/Store 构建验证，不能只靠客户端拼 route ID。Task 项目、Session 项目、网络 grant 项目同事务一致；旧无项目 route grant 保留历史但不可供新 Task/Turn/项目操作使用。account balance 明确为 Host 级，不混作项目 route 授权。

项目 route 被移出 allowed_route_ids 后，下一准入拒绝；Host URL/key/model 变化仍触发原网络 stale；新授权不能自动替换旧 Task 的具体 grant。项目选择不影响已有 Task 的网络归属。错误须保持 dispatch_state/calls，不丢未知发送事实。

## 5. 接口与幂等

公开项目 DTO 使用新 project_config 模块，避免给 RunRequest/Task 直接增加必填字段破坏历史 JSON。B 提供唯一 Engine/Store 业务实现，C 只消费，不在 HTTP/CLI 复制 SQL 或权限规则。ID/元数据按既有安全验证；所有新增管理路由要求 token，严格 JSON 和错误脱敏。

| 操作 | HTTP | 返回/约束 |
| --- | --- | --- |
| 列表 | GET /api/projects | 保留 Project[] |
| 登记 | POST /api/projects + Idempotency-Key | {name,root_path}；201 Project，配置另GET；重复相同请求返回原事实 |
| 项目详情 | GET /api/projects/{id} | Project，未找到 404 |
| 默认选择 | GET/PUT /api/project-selection | {project_id,revision}；PUT {project_id,expected_revision}；首次 revision=0 |
| 项目配置 | GET/PUT /api/projects/{id}/config | PUT {expected_revision,config}；整体替换、CAS |
| 显式新任务 | POST /api/projects/{id}/runs + Idempotency-Key | {expected_config_revision,request:RunRequest} |
| 旧新建入口 | POST /api/runs | 形状不变；先旧幂等回放，再解析持久默认项目；无选择拒绝 |
| 项目历史 | GET /api/runs?project_id=ID | 无参数仍全部；依据领域归属筛选 |
| Task 绑定 | GET /api/tasks/{id}/project | 新绑定/当前权限状态或明确 legacy_unbound 状态 |
| 会话新回合 | 既有 Session turns 路由 | 不增加 root/project 覆盖参数，原 Session 决定项目 |

选择 CAS stale 不自动重试到新项目；配置 CAS stale 不暗中刷新后重发。UI 草稿携带捕获的 project/config revision，其他窗口改变默认选择不能让已编辑内容悄悄发送到另一个项目。

显式项目新建指纹版本化包含 project_id、expected_config_revision 和 RunRequest。旧省略项目入口首先按原请求 hash 查既有 key；命中返回原 A，即使当前选择 B、A 根离线/撤权，也不重新执行。首次解析的项目绑定必须持久化。同 key 显式 A/B 冲突，不能借不同入口绕过 key 唯一性。登记请求重放也必须先于依赖当前文件系统的写入判定。幂等记录、Task/Session/Turn、项目 sidecar 与 grant binding 同事务提交，任一失败不得留下混合快照或发起调用。

业务错误采用稳定 project_* code：invalid=400、not_found=404、revision_conflict/duplicate_root/overlapping_root/selection_required/legacy_unbound/root_changed/root_unavailable/permission_revoked=409，unsupported=409，内部持久化损坏=500（固定脱敏消息）。已有网络错误码与 dispatch 语义保持，不能全部包成无调用信息的 409。具体枚举与 DTO 命名经短预审附录定稿。

CLI：project list/create/get/current/select/config get/config set；run start --project ID --expected-config-revision N（两项成对的显式路径）或两项都省略的旧默认路径；run list --project；network route preview/authorize 与 route models/check 明确 --project。project select 带 --expected-revision N；config set 读取 --file 指定的完整 ProjectConfig JSON 文件并带 --expected-revision N；不接受省略字段时自动扩权。CLI 只通过 HTTP 调用 Host。

Web：增加登记/选择/权限配置；显示 Host 共享设置和项目独立授权；新建请求明确 project/revision。已有聊天从 RunContext 解析 Session，后续消息走 Session new Turn，resume 仅中断恢复。历史聊天显示其真实所属项目，切默认项目不改变已打开会话。旧 legacy_unbound 显示限制与新建入口。错误/冲突保留草稿，不自动批准或重发。

现有 WASM list 可按明确项目或当前项目验证根后只读列出；WASM run 在新项目模式返回 project_operation_unsupported，本片不借旧全局目录入口绕过项目权限，不声称完整插件能力已接入。

## 6. schema11、失败与恢复

## 9. 冻结 Rust 接口与补充裁决

以下类型由 B 在 project_config 模块维护，均 Serialize/Deserialize 严格字段（内部 RootIdentity 不从外部请求接收）：

```rust
pub struct ProjectConfig {
    pub allowed_route_ids: Vec<String>,
    pub default_route_id: Option<String>,
    pub tools: bool,
    pub write_scopes: Vec<String>,
    pub allow_commands: bool,
}
pub struct ProjectConfigSnapshot {
    pub project_id: ProjectId,
    pub revision: u64,
    pub config: ProjectConfig,
    pub permission_digest: String,
}
pub struct ProjectSelection { pub project_id: Option<ProjectId>, pub revision: u64 }
pub struct RegisterProject { pub name: String, pub root_path: String, pub idempotency_key: String }
pub struct ConfigureProject { pub project_id: ProjectId, pub expected_revision: u64, pub config: ProjectConfig }
pub struct SelectProject { pub project_id: ProjectId, pub expected_revision: u64 }
pub struct StartInProject { pub project_id: ProjectId, pub expected_config_revision: u64, pub request: RunRequest, pub idempotency_key: String }
pub struct TaskProjectBinding {
    pub binding_version: u32,
    pub task_id: String,
    pub project_id: ProjectId,
    pub root_identity: RootIdentity,
    pub config_revision: u64,
    pub permission_digest: String,
}
```

Engine 公共方法：同步 `project_config(&ProjectId)->Result<ProjectConfigSnapshot>`、`current_project()->Result<ProjectSelection>`、`task_project_binding(&str)->Result<Option<TaskProjectBinding>>`、`project_workspace(&ProjectId)->Result<PathBuf>`、`project_runs(&ProjectId)->Result<Vec<Run>>`；异步 `register_project(RegisterProject)->Result<Project>`、`configure_project(ConfigureProject)->Result<ProjectConfigSnapshot>`、`select_project(SelectProject)->Result<ProjectSelection>`、`start_in_project(self:&Arc<Self>,StartInProject)->Result<Run>`。Result 沿既有 anyhow；ProjectError 可 downcast 且提供 `code()->&'static str` 和固定安全 Display，C 按 code 稳定映射。现有 Store::projects/project 查询保持。permission_digest 算法需版本化，覆盖规范排序/去重后的权限；Task digest 覆盖 Task 实际权限而非仅配置上限，配置和 Task 的不同摘要不可误相等比较。

GET Task project 返回 `{binding:TaskProjectBinding|null,status:"bound"|"legacy_unbound"}`，不要求读取实时根；实时有效性由操作入口检查，不能把 bound 当授权通过。Config PUT 请求保持 §5 的 `{expected_revision,config}`，GET 返回 ProjectConfigSnapshot；不采用预审提案中的扁平混合 DTO。

NetworkSubject 保留现有 kind/id；增加 `project_id:Option<ProjectId>`，serde default 且 None 时不序列化，旧JSON/摘要v1仍原样可读。route 新操作必须 Some，account 必须 None；新 route key/digest 纳入 project，版本2。旧无项目 route 仅历史查询/撤销，不能新的 preview/confirm/admit。Engine 新增 `project_route_models(&ProjectId,&str)` / `project_route_check(&ProjectId,&str)`，返回原 NetworkResponse；旧 route_models/check 方法只可解析 current 后委派新方法，不访问 legacy grant。HTTP 原 route models/check POST 接受 `{project_id}`；旧空请求只可解析 current，不能落旧全局 grant。CLI/web新请求明确带项目；account不加项目。

两新网络方法为 async，分别返回 `std::result::Result<NetworkResponse<Vec<String>>,NetworkError>` 与 `std::result::Result<NetworkResponse<serde_json::Value>,NetworkError>`。NetworkErrorKind可增加稳定project_*拒绝变体，须与ProjectError固定code一致；保留dispatch_state/calls，特别check第一调用完成后下一准入失败不能丢前一回执。现有preview/confirm签名和ConfirmRequest不变，不在confirm重复新增project字段；safe_error不可吞掉项目业务错误变成Internal。
