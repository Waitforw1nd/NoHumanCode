## 1. 目标、依据与边界

用户通过 CLI/HTTP 查看现有 builtin.files 的持久期望状态、当前进程实际状态及在途文件 lease；显式启用/禁用跨 Host 重启保持。仅 Host 作用域、固定 builtin.files@1.0.0，连带其 builtin.engine-tools@1.0.0 consumer；两者不拆成两个可独立管理的插件。范围是现有 read_file/write_file，不承诺撤销所有文件访问。list_files/search_files/run_command/run_wasm仍如实标为compat来源（run_wasm仍受现行项目策略拒绝），原Task权限、审批和网络约束不变。

依据：B第七轮《阶段一剩余范围只读建议》、项目书阶段一第1/2/8项及NEXT-05/08/09有效验收。只读核查发现：ToolRuntime::builtin每次启动直接start consumer；acquire持runtime mutex调用同步admit，Store claim先commit，lease单次且不可Clone；disable stop_subtree撤销effect但不撤销已发lease；PluginHost Failed不得直接start，unload保留recovery记录；Engine::new没有持久启停读取；Store现schema11；HTTP/CLI尚无plugin命令。

本片不做外部发现/安装/卸载/热替换、WASM/process runtime、其余compat插件化、Desktop/Web改造、完整Team/MCP、预算或工作树产品化。保留项目书剩余目标，不以此片称完整阶段一完成。公开命令叫禁用，不叫卸载；内部unload仅用于清理/显式重建固定assembly及测试。

## 2. 持久事实与当前观察

新增src/plugin_management.rs（B）承载公开DTO/typed error及必要Store扩展；D的运行时DTO置于tool_runtime，不依赖未合入的B模块。所有公共DTO Serialize/Deserialize，拒绝未知请求字段。

PluginDesired：plugin_id="builtin.files"，enabled:bool，revision:u64（SQLite范围0..=i64::MAX），updated_at:i64。新库和11→12升级初始化enabled=true/revision=0；保留既有默认行为。只允许这一行。版本号属于固定manifest，不能从请求设置。

PluginStatus：
- plugin_id、version="1.0.0"、scope="host"；desired:PluginDesired。
- runtime:FilesRuntimeStatus（D提供），其中 state 为 active/stopped/unloaded/failed（failed不伪装active）；admission_open:bool；in_flight:u64；draining:bool；instances列出provider/consumer的实际state及可空failure_stage；providers列出当前真实注册的服务键及provider_id；effects_count、subscriptions_count；recovery为脱敏结构{plugin_id,stage,cause_code}，不公开任意PluginError.message或payload。
- affected_tools固定[read_file,write_file]，compat_tools固定四项；affected_dependents固定[builtin.engine-tools]。
- converged:bool：期望enabled时要求真实provider+consumer Active且admission_open；期望disabled时要求新准入关闭、文件注册effect/订阅撤销、实例为stopped/unloaded且无本次停止失败。in_flight>0不使已完成禁用变成未提交，另以draining=true明确旧lease尚在。
- blocked_reason为null或固定枚举disabled/runtime_failed/runtime_unavailable；历史recovery不自动当作本次失败，失败记录不会被重新启用擦除。

snapshot只读、短锁内组合持久desired与runtime；不自动修复、启动、停用、重试或递增revision。in_flight是取样时尚未释放的文件lease数量，包括已claim但尚未执行/正在执行者；不是进程恢复后的持久执行计数。工具任务的claimed/unknown仍从既有审批/回执读取，不能靠in_flight=0宣称无未知副作用。

SetPluginEnabled：enabled:bool、expected_revision:u64。Idempotency-Key作为独立必填参数。PluginMutationReceipt仅记录不可变持久命令事实{plugin_id,enabled,previous_revision,revision,committed_at}；每个新的有效key、CAS成功的命令revision恰+1，即使目标enabled不变也形成一次显式协调意图。溢出拒绝。PluginMutationResult={receipt,replayed:bool,current:PluginStatus}。receipt不是实际停启成功证明；current是本次观察，回放可不同于原观察。

## 3. CAS、幂等与schema12

新增schema12迁移标记builtin-plugin-management-v1；两个sidecar表：plugin_desired（固定id、enabled整数0/1、非负revision、updated_at整数）、plugin_management_requests（key主键、plugin_id外键、enabled、expected_revision、result_revision、committed_at及严格约束）。可用等价明确定义列实现receipt，但须在报告附实际DDL/约束；不要存原始任意请求/敏感字符串。key沿用secrets::validate_idempotency_key，HTTP重复/逗号合并header拒绝。表PK/FK/CHECK/字段类型与迁移标记都验证，不能只验证表名列名。

Store Immediate事务顺序：验证已知plugin/请求/key→先按key查原事实→若同一plugin、enabled、expected_revision精确相等，返回原receipt且replayed=true（即便当前revision已前进）→同key异参冲突→新key才比较当前revision→CAS成功更新desired并插入receipt→commit。两条记录原子提交；失败无半行、无revision漂移、不消耗key。不同key同expected_revision最多一项成功。请求相等比较显式字段，不依赖JSON对象顺序。管理幂等命名空间与旧业务幂等分开，不写旧Task/Turn事件来伪造管理归属；requests表本身是持久管理审计事实，本片不新增管理SSE流。

新库、schema11非空迁移、已有12重开与损坏schema拒绝均验证；旧Task JSON、approval v2、workspace/change/checkpoint/network/project sidecar、secret密文字节原样保全。SCHEMA_VERSION=12，调整11验证的上界而非跳过旧校验。不得改写NEXT-09既有恢复事实。

Store管理写入口仅crate内供Engine在runtime管理锁下调用，客户端不得直接调用SQL。Store::claim_approval对write_file还须在既有Immediate事务内重核desired.enabled（除现有权限/封存等检查外）；不能新增一个先读后claim竞态。读工具的最终准入在runtime锁下检查运行状态并经Store复核期望enabled与项目权限。已获lease的perform_tool结果落库不再次以禁用为由否认原claim。

## 4. 锁序、禁用先后和lease

支持现行单Host/单Engine协调，不承诺多个活跃Engine共用同库。所有管理set与snapshot和acquire串行于同一ToolRuntime mutex。顺序固定runtime→Store短事务；如外层需要Engine gate，必须gate→runtime→Store，绝不能Store锁内进入runtime、runtime锁内await/gate/执行文件工具。本片管理无需Engine gate；D回调同步且短，只可读/写Store或组织DTO。

D提供pub(crate) with_files_control<R>(&self, f: impl FnOnce(&mut FilesControl<'_>)->Result<R>)->Result<R>，FilesControl仅暴露snapshot()与reconcile(enabled)，不暴露PluginHost、service、guard或任意执行句柄。B在该锁内先Store CAS commit，然后仅新命令调用reconcile，最后组合current。snapshot查询亦通过此锁后读Store。实现可调整内部组织，但改变此签名先通知经理和依赖方，不让C/B私写stub。

禁用的线性化点是持有runtime锁时desired=false的事务commit。commit之后先关新准入，再按consumer→provider停止并撤销注册/订阅，最后释放锁。禁用DB失败时runtime保持原状；不能先停后回滚持久状态。若commit成功而清理失败，新准入保持关闭，实际failed+recovery可见；receipt仍表示持久期望已接受，不能回滚desired或伪称禁用完全收敛。

claim先赢：在runtime锁内通过现有审批和持久claim后发出单次lease；随后禁用允许旧lease按原绑定完成并持久化真实结果。禁用不制造cancelled、不改变审批decision、不重复文件写。若本身取消/根身份/权限等既有检查拒绝，按旧语义处理，不保证所有旧lease必然执行。disable先赢：后续read/write acquire在admit前拒绝，claim/FS/Provider不能因管理命令增加。审批等待时没有lease；approve仍是决定，之后最终acquire若disabled则零claim/零FS，不伪造已执行。保持有权限的compat正控，防止误称全文件访问已撤销。

文件lease用私有RAII计数，成功admit后计入，execute结束/失败/丢弃都准确减少；计数减操作不再次获取runtime锁，避免Drop锁死。返回lease后的无await分配路径须无可恢复失败；任何claim失败不得计入或获得执行能力。不能把原始service Arc公开给Engine/HTTP。

## 5. 启用、重启与失败恢复

ToolRuntime::builtin保留现有组件兼容；新增pub fn builtin_with_enabled(enabled:bool)->Result<Self>构造固定assembly，false不得先activate再stop。Engine::new先读取持久desired，才装配runtime，再暴露HTTP；读取/损坏持久状态失败则Host启动失败，不回退enabled=true。启用：同一管理锁下desired=true先commit，固定provider→consumer启动，只有完整成功才打开准入；失败rollback撤销effect，admission关闭，当前state failed/recovery可诊断，Host可继续服务查询。

固定builtin lifecycle失败应留在runtime诊断而非令Engine完全不可查询；仅锁毒化/内存/持久数据等无法安全构造才返回初始化错误。不得吞错误并fallback旧Workspace直接执行。Failed实例需按既有Host规则停止残留并unload后显式重建，不直接start Failed；保留recovery历史。再次set enabled=true（新key、当前revision）可显式协调；same-key纯回放不再次激活/停用，GET也不协调。新key、same enabled同样revision+1，解决先前收敛失败，而不是用旧key隐式重试。

commit前进程终止：持久状态未改变；commit后、runtime apply前终止：重启按已提交desired初始化。每次Host启动只进行一次固定assembly初始化；失败不循环重试。desired=false跨重启不激活provider/consumer，effects=0且准入关闭。desired=true启动只构造服务，不启动任何旧Task、重试unknown或更换grant。运行时实际状态、句柄、lease不序列化。旧receipt仍只表示当时CAS持久接受，与新进程current分离，禁止持久化上次active后冒称本次active。

runtime apply之后HTTP响应丢失：用户可用原key、原参数手动回放，返回原receipt+现在current，不再协调。若status采集故障发生于已commit之后，返回安全internal错误、明确不能推断未提交；CLI提示结果未知和原key查询/手动回放，不自动重试、不产生新key。锁毒化一律fail-closed；不可沿用原有效服务继续准入。已批准与执行事实、unknown不重试、恢复后原Task拒resume、checkpoint原Conflict优先及complete后合法显式新Turn都保持。

旧Engine::disable_builtin_files/unload_builtin_files是内存组件入口而非新持久管理API。保留兼容签名和既有测试，明确仅内存诊断控制；不挂HTTP/CLI，不用它们替代本契约set。运行中被旧入口停止时desired可true而runtime stopped/unloaded，这应真实显示不收敛；正常新命令可显式协调，重启按desired。原NEXT-05验收不倒写为持久启停。

## 6. 固定应用/HTTP/CLI接口

B提供Engine同步方法，均anyhow::Result且业务错误可downcast至PluginManagementError：
- plugins() -> Result<Vec<PluginStatus>>（只含一个可管理builtin.files）；plugin_status(&str) -> Result<PluginStatus>。
- set_plugin_enabled(&str, SetPluginEnabled, &str /* key */) -> Result<PluginMutationResult>。

Typed error至少Invalid、NotFound、RevisionConflict、IdempotencyConflict、Unavailable、Internal；code固定plugin_invalid/plugin_not_found/plugin_revision_conflict/plugin_idempotency_conflict/plugin_unavailable/plugin_internal。对外用固定消息，无SQLite/绝对路径/插件原错/秘密透传；内部错误链可保留但证据仅安全码。

HTTP：GET /api/plugins → {plugins:[PluginStatus]}；GET /api/plugins/{id} → {plugin:PluginStatus}；PUT /api/plugins/{id}/enabled，严格JSON {enabled,expected_revision} + 必填Idempotency-Key → PluginMutationResult。成功200表示持久命令接受，current.converged才表示当前收敛；不新增混淆意义的ok字段。新旧key回放均200。启停失败但desired已commit也200+current.failed/converged=false，不当作事务未接受。

仅新plugin路由错误：{code,message,error:message,retryable:false}，Invalid400、NotFound404、两个Conflict409、Unavailable503、Internal500；JSON/content-type/size/token沿用现有ContractJson/guard的400/415/413/403规则。读写均token保护且遵守origin/loopback；GET不因匿名而暴露runtime诊断。拒绝重复/未知字段、null/浮点/负数revision、非bool、缺失/重复key；固定插件名外的路径404，不接受路径/文件/可执行输入。不得改变旧error DTO或全局映射制造回归。

CLI固定命令：plugin list；plugin status builtin.files；plugin set-enabled builtin.files --enabled true|false --expected-revision N --key K。仅经本机Host，先bootstrap token，适用所有plugin GET/PUT；不得读SQLite/密钥/文件工具或启动Host。--json保留上述响应完整形状，human输出明确desired/revision、runtime/admission/in-flight/converged、仅影响两个工具、compat仍受原策略。PUT已接受但未收敛输出receipt/current并返回非零（1），不要伪造网络失败或未提交；JSON仍为成功响应对象。普通已收敛返回0，原错误退出规则保持。响应丢失提示未知，保留原key/原参数，不自动重发。无需main改动，若clap接入确实需要仅C可改且报告原因。
