## API 与公开封闭 DTO

公共类型放 `runtime_management`；B 首先公布实际 Rust 签名并保持以下语义和 JSON 字段不变：

```text
RuntimeId = ChatAgent | CompletionProvider
RuntimeId::parse(&str) -> Result<RuntimeId, RuntimeManagementError>
Engine::runtime_components() -> Result<Vec<RuntimeComponentStatus>, RuntimeManagementError>
Engine::runtime_component_status(RuntimeId) -> Result<RuntimeComponentStatus, RuntimeManagementError>
Engine::set_runtime_enabled(RuntimeId, SetPluginEnabled, &str)
    -> Result<RuntimeMutationResult, RuntimeManagementError>
```

三个 Engine 方法均同步，不持短锁跨 await。允许内部共享 helper，但旧 plugin 入口白名单仍只有 files/shell；不能把底层四 ID 扩展直接暴露给旧 API。

HTTP：

- GET `/api/runtime/components` 返回 `{"components":[AgentStatus,ProviderStatus]}`，固定 Agent 后 Provider；分别采样，不承诺跨组件原子快照。
- GET `/api/runtime/components/{id}` 直接返回 RuntimeComponentStatus。
- PUT `/api/runtime/components/{id}/enabled` 请求严格 `{enabled:bool,expected_revision:u64}`，revision<=i64::MAX；单一合法 Idempotency-Key。响应直接 RuntimeMutationResult。
- 仅上述两个固定 ID；files/shell 和其他 ID 在这个入口返回404。保留旧 `/api/plugins` 三类操作、旧 Agent 诊断 `/api/runtime/agents/chat` 与 `runtime agent status` 的 DTO 和行为。

RuntimeComponentStatus 严格字段：

```text
id: "builtin.chat-agent" | "builtin.provider-xpeach"
capability: "agent.strategy@1.0.0" | "provider.completion-codec@1.0.0"（与id对应）
desired: {scope:"host", enabled:bool, revision:u64, updated_at:i64>=0}
runtime: AgentState | ProviderState
converged: bool

AgentState:
  kind:"agent", scope:"process",
  active:bool, admission_open:bool, in_flight:u64, generation:u64>=1,
  draining:bool, transitioning:bool, effects:u64, recovery:u64,
  last_failure:null | unavailable/invalid_decision/failed/panicked/stopped/busy/lifecycle/internal
ProviderState:
  kind:"completion_provider", scope:"process",
  active:bool, admission_open:bool, in_flight:u64, generation:u64>=1,
  transitioning:bool, effects:u64, recovery:u64, lifecycle_failed:bool

RuntimeMutationResult:
  receipt: PluginMutationReceipt（原字段plugin_id/enabled/previous_revision/revision/committed_at）
  replayed: bool
  current: RuntimeComponentStatus
```

所有层级封闭，不允许额外字段、重复 JSON key、任意错误原文或任意 Map。generation/in_flight 为完整 u64，不误套 SQL revision 上限。时间非负，真实新 receipt committed_at>0。Agent旧诊断继续保留原完整结构，禁用初始 generation=1，不伪造激活。

同一组件状态采样按 runtime锁→Store，取得持久 desired 与短锁内状态投影；是当时观测，不是其他进程实时状态或后续准入承诺。transitioning 的 effects/recovery 是最近稳定快照。

收敛公式：

- 两者通用：无 transitioning、无 lifecycle failure/Agent last_failure、recovery=0。
- desired=true：active && admission_open（Agent同时!draining）。
- desired=false 的 Agent：!active && !admission_open && !draining && in_flight=0 && effects=0。
- desired=false 的 Provider：!active && !admission_open && effects=0；允许已准入旧 Completion in_flight>0。
- Agent draining 始终等于 !admission_open && in_flight>0。非transition时 admission_open 必须蕴含 active。跨实例改意图可使状态不收敛，不能伪装同步撤销。

## 意图提交、回放、Busy 与生命周期

锁序：可选原 async gate → 单个 runtime 短锁 → Store连接锁 → SQLite事务。不同时持两个 runtime 锁、不反向取锁、不跨 await。Store 不调用 runtime/plugin，不持任何这些锁或事务调用生命周期、策略、codec、未知析构。

持 runtime 锁进入 Store 的 IMMEDIATE 管理事务；输入已验证后，事务先查全局 key：

1. 同 key 同 ID/enabled/expected_revision 回放原 receipt，忽略当前 CAS/Busy，不再次执行生命周期。
2. 同 key 参数不同返回 IdempotencyConflict，包含跨四 ID 冲突。
3. 仅新 key 检查进程状态：任一 transitioning 全部 Busy；Agent draining 的 enable Busy，disable 可提交但不重复 stop；失败/已耗尽代次的 enable Unavailable。其后比较 CAS，再原子写 desired 和 receipt。
4. 同状态新 key 仍需 CAS 并递增 revision，但稳定且已匹配时不重复 start/stop。Busy/Unavailable/冲突不提交、不消费 key。enable需递增代次而已达上限时，在提交前Unavailable；disable遇代次耗尽仍可提交false、关准入并显式记录失败，不能留下权限。
5. commit失败不改变本地admission/generation。成功后在同runtime锁内保留本次transition，再释放所有锁执行回调。回调失败仍返回已提交receipt与非收敛current，不能把已提交意图伪装成未提交。
6. lifecycle失败后不能通过新enable静默清除；disable可记录false并保持关闭。恢复通过Host重启依据desired重建，本片不增加repair后台服务。相同key回放只取证，不触发修复。
7. 提交后current读取失败可返回Internal；客户端按可能已提交处理。只读current不能证明某个key成功，操作者用原key与原参数显式回放取回原receipt；本片不新增按key查询路由，不自动重发写入。

Agent disable提交后关新lease；已准入任务保留策略/effects直到最后lease释放，再锁外stop。Provider disable提交后关新prepare/acquire、使旧prepared代次失效，锁外stop撤effects；已准入Completion继续。两者不可强套同一排空实现。

startup desired=false：只注册catalog/factory，零start/activation/effect，Host仍可启动、读管理与旧持久事实；desired=true激活失败维持原fail-closed构造。先构造成功的其他runtime也需锁外安全清理。新代次最小1。

回调完成后如发现另一个Store改变desired，不能宣称已按原回执收敛；可以保持安全的本地状态并显式不收敛。最终准入始终校验DB，不能仅靠回调结束时再读一次防竞争。不承诺跨进程广播。

## 最终准入与旧 Rust 兼容

Agent新lease的线性化点为runtime锁内，IMMEDIATE事务检查持久enabled=true并成功commit。绑定解析、可失败准备、计数溢出检查先完成；commit后同锁内不可失败地增加in_flight并交付lease。Store失败不准入、不用cached true。独立Store之后提交disable是后发生，已准入lease可继续。commit后进程崩溃不能凭空获得可继续执行的lease。

Provider prepare保存同一次DB读取的enabled=true与revision，并保存本地generation/effect。可锁外encode/decoder，但最终acquire在runtime锁内复核generation/effect，并在**现有网络/预算准入同一个IMMEDIATE事务**校验enabled=true与expected revision，随后claim/预算预留/commit。任何revision变化（包括同值新意图）使旧prepared拒绝。外部false→true不能复活旧prepared；新prepare可读取当前true，不强制旧Engine整体重启，因为本片不改变codec配置。

拒绝新准入不得创建网络/预算claim或发送请求。提交后的ProviderPermit构造仍可能失败：保留现有finish补偿及claimed/unknown崩溃语义，不宣称commit后绝无失败、不重发unknown。Store锁不得递归获取。所有早退、prepared/decoder、部分激活Host和最终runtime析构均在锁外guarded处理；保留普通panic hook行为与固定安全诊断。

旧公开 Rust enable_builtin_agent/disable_builtin_agent、enable_builtin_provider/disable_builtin_provider **保留签名及“仅进程内控制、不写持久账本”的兼容含义**，避免伪造无key/CAS的持久写：

- local disable是临时抑制，不改变desired/revision/receipt，重启按持久意图。
- local enable必须在runtime锁下读取持久enabled；false时返回安全Unavailable且不启动；true才可按原生命周期尝试启用。它不替代最终事务准入，即使之后远端disable也不能越权。
- 公开新持久管理遇本地抑制且desired已true时，新key同值true会提交revision并恢复本地运行；旧key回放不驱动。
- 旧Rust状态接口仍报告进程状态；新管理状态显式desired/current差异。既有Rust生命周期测试保留，D补持久false下不能绕过的反例。

Models/Balance原调用和账本不受Completion开关控制。route check先完成Models后Completion拒绝，应保留已发生Models回执；不能编造“无网络调用”。异步Task创建回执不变，运行期拒绝记录failed/cancelled，不能说任务未创建。

## HTTP、CLI 与错误

CLI固定：

```text
runtime component list
runtime component status <id>
runtime component set-enabled <id> --enabled <true|false> --expected-revision <n> --key <key>
```

支持原全局--json及human，成功exit0、已验证业务拒绝/未知结果exit1、参数错误exit2。只消费Host事实，不直读SQLite或绕过权限。写命令无自动retry/redirect；收到不可信/截断/超长/断线响应应固定“结果未知”，保留原key供人工同参回放，不能猜测未提交或换key重试。

新GET显式纳入authenticated_read；继承token、Host、Origin、Sec-Fetch-Site、安全响应头/no-store。认证/安全guard先于handler；安全guard和方法错误沿现有框架。GET/HEAD不产生管理写，PUT仅enabled子路由；无业务query，拒绝任意query及不允许的body，方法错误不执行。

请求/响应按原始JSON字节拒绝重复key，再做封闭字段/类型/身份/状态关系验证；不能先Value丢重复字段再声称拒绝。复用现有有界响应读取；新的客户端最大JSON正文固定256KiB，服务端PUT正文最多4KiB，超限安全拒绝。成功需application/json；失败只输出固定安全码/消息，不回显任意异常、URL、token。

RuntimeManagementError固定：

| variant / code | HTTP | 固定message |
| --- | --- | --- |
| Invalid / runtime_invalid | 400 | Invalid runtime management request |
| NotFound / runtime_not_found | 404 | Runtime component not found |
| RevisionConflict / runtime_revision_conflict | 409 | Runtime revision conflict |
| IdempotencyConflict / runtime_idempotency_conflict | 409 | Runtime idempotency conflict |
| Busy / runtime_busy | 409 | Runtime transition busy |
| Unavailable / runtime_unavailable | 503 | Runtime component unavailable |
| Internal / runtime_internal | 500 | Runtime management outcome unavailable |

业务错误envelope严格 `{code,message,error,retryable:false}`，error=message。Busy/Unavailable仅用于已知未提交的新写拒绝；commit或提交后状态读取不确定统一Internal。客户端须核HTTP status和code对应。receipt必须与本次ID/enabled/expected_revision匹配且revision=previous+1；current独立合法即可，不能要求等于旧receipt。
