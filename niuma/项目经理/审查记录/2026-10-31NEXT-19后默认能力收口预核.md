## 项目书要求与实际入口

依据[项目书第五节](../../../PROJECT-BOOK.md)。以下区分已有功能与默认插件组合，不用缺少同名文件推断功能不存在，也不用功能存在推断组合已经完成。

| 项目书默认项 | 当前实现或入口 | 收口需要证明 |
| --- | --- | --- |
| core | domain、Store、Engine及Host装配 | 稳定Host职责与可替换能力的明确边界；核心状态不能出现第二权威 |
| session-log | Store事件、Session/Turn投影、HTTP/SSE | 真实注册/依赖与事件消费生命周期；保留游标、幂等、恢复语义 |
| local-project | project_config、workspace_identity、Project公开入口 | Project作用域与组件依赖相符，禁用/重启不绕过权限根 |
| workspace | workspace、workspace_changes、git_worktree | 生命周期与已准入副作用、unknown、恢复的关系明确 |
| provider-xpeach | builtin.provider-xpeach、ProviderRuntime | 已有Completion codec绑定与持久管理；默认组合依赖、替换及当前Models/Balance边界须明确 |
| file-read-search | builtin.files的read/list/search | 已有真实绑定与准入；在完整组合中验证依赖、撤销及恢复 |
| approval-policy | approval与Host策略 | 权限与审批事实继续由Host强制；策略扩展不能授予超出Host权限的执行权 |
| file-write | builtin.files的write及Host批准事务 | 与只读能力共享实现事实如实登记，禁止仅靠名称分项声称有两个独立组件 |
| shell | builtin.shell及command_execution | 保留一次执行权、网络告知、取消/unknown和持久禁用 |
| git-diff | git_diff及Engine/CLI入口 | 真实组件提供/消费关系、作用域、生命周期与同一Host权限 |
| checkpoint-restore | checkpoint、workspace_changes及公开入口 | 保留恢复范围、冲突、封存及账本，不把注册一层wrapper当作交付 |
| recovery | Store::recover及应用对账 | 启动时顺序与失败可诊断，关闭可选组件不妨碍读取/恢复已存在事实 |
| chat-agent | builtin.chat-agent、AgentRuntime | 已有策略绑定与持久管理；完整依赖与用户链继续验证 |

源码实核：tool_runtime.rs分别建立files/shell的PluginHost；agent_runtime.rs和provider_runtime.rs分别建立各自PluginHost及consumer/provider绑定，manifest目前声明Cli/Headless。Engine持有这些实际runtime。上述设计提供现有生命周期隔离，不能只凭“多个Host实例”判错，也不能据局部依赖解析宣称整个默认组合依赖图已经验证。后续必须以生产装配/撤销/替换调用链决定是否需要组合层，不能预定增加空壳统一类。

## NEXT-19之后应先冻结的验收问题

1. 逐默认项明确必需服务、可选组件、作用域、实际提供者和消费者；项目书名称与现行兼容ID的映射必须显式记录，不全局改名。
2. 明确禁用/卸载必需依赖时拒绝、排空或恢复的规则；不能关闭审批强制或持久恢复后仍允许新副作用。
3. 跨组件替换/缺依赖/版本不符/激活失败必须在真实装配上验证；依赖清单和诊断输出不能代替效果可撤销。
4. 将已有NEXT-16同一新用户故事与NEXT-18持久管理放入同一最终受测组合，证明默认能力加载、禁用/再启用、重启、恢复和旧fallback；不重复宣称已有功能从零实现。
5. 收口构建启动说明和可复现交付，再让正式Desktop消费同一Host协议。Desktop页面、审批/工具/Diff/恢复、Team与声明式扩展和浏览器E2E仍按项目书完整要求交付。

完整Team、MCP、Skills、复杂上下文压缩、高级KeyPool以及长期插件运行时目标没有因本表而删除。NEXT-19结果原子性只是其中一个内核边界；整个项目完成须按项目书逐项验收。此预核未运行测试、没有产品修改、未创建新员工或新实现任务。
