## 审查退回与修复

1. unknown 不允许通过任意同域操作结算别人的任务/网络回执。A 添加原操作内的 task/call 绑定；B 在真实 worker 预留和网络 claim 事务处接线，结算先核绑定。C 增加独立同域不同操作反例。仅同 epoch 仍不足以替代原操作身份。
2. restore 的 generation 预留不替代文件效果前验证。B 已在每次 remove/atomic_replace 前核原授权，且仅在实际动作即将开始时设置 action_started。没有实际文件效果且失败回执成功保存，可确定收束；部分效果或结果持久化不确定保留原 owner。
3. 普通 write_file 同样必须在 create_dir_all/atomic_replace 前重验。WRITE_AUTHORITY 由持有真实 FileEffectGuard 与同域 Store 的内部 scope 承载，不能仅用布尔标记。直接 public write_file 和 run_wasm 入口仍拒绝绕过 Host 持久 claim。
4. COMMIT 失败若能用原 Transaction 明确完成 ROLLBACK 并确认 autocommit，可保持同 controller 后续使用；不能把此类已确定失败一律标 unknown。无法确认则封门并保留原 owner。C 使用真实 deferred-FK COMMIT 失败验证回滚后无行泄露及下一操作成功；E 恢复原 runtime 正向重试断言。
5. D 最初将崩溃 schema18 快照改为 schema17 再恢复的改法被退回。修复保留原始证据副本，仅在原文件/原身份上查询、恢复、再次打开，保持业务结果与 no-replay 断言。
6. C 曾把旧 restart_and_http_security 放在默认未启用的 feature 下，此状态不能接受。要求恢复默认测试覆盖，将需要 crate 内真实能力的原用例放入默认 unit 测试并保留 HTTP 安全、恢复及幂等断言；A/B 移除不再使用的 feature 和测试扩展接口。

仍待完整回归及最终审查。可信 bootstrap 与 W07 不能称为完整 W3 公开生产执行；公开 run_wasm 的权限、持久结果及恢复链尚未据此验收。
