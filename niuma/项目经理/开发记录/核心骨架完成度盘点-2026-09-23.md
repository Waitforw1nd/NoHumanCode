# 核心骨架完成度盘点

日期：2026-09-23。整理人：项目负责人。

**按项目书定义的完整核心骨架，当前估计完成约四成，合理区间为 35%～45%。会话数据、连续回合应用服务和现有 HTTP/SSE 已有经过验收的基础；插件 Host、逐次审批、完整工作区变更管理和开发者 CLI 尚未形成完整链路。**

## 1. 这个比例怎样理解

这是负责人依据当前能力覆盖范围给出的阶段粗估，没有按工时加权的完整任务分解，因此不是精确测量，也不能据此推算还需要多少天。它不表示代码量完成率、测试覆盖率或整个产品的发布完成度。

这里的“核心骨架”包括项目书要求的 Host 插件与权限中心、领域持久化、应用执行、协议与事件、Provider、Workspace，以及验证这些能力的 CLI。完整 Desktop 页面、高级 Team、MCP/Skills、复杂上下文压缩和高级 KeyPool 不作为本轮核心骨架必须同时完成的功能。

估计依据是下表各模块的实际覆盖：领域/传输基础较完整，执行/Provider/Workspace 已有部分实现，插件/审批/CLI 仍有整块缺口。不能按“三位员工全部通过”推算整个架构已全部通过，也不能把 99 项测试当成项目完成百分比。

协议存在 AwaitingApproval 枚举和 approval.requested/resolved 事件名，仅代表预留了名称；是否完成审批必须看真实的请求、决策、执行拦截和重启恢复链路。

## 3. 第一轮成果的价值

A/B/C 稳定了会话数据、连续回合应用服务和传输三层，为后续模块提供了可复用基础。当前应保留已验收的不变量，在其上增加插件与审批边界；没有发现必须整体推倒这一基础的架构证据。

后续若为满足项目书重构 Engine、Provider 或工具调用入口，应以明确替代范围和迁移方案实施，保留幂等、事务、归属、取消和恢复行为。新模块不能绕过已建立的数据入口。

最近留档的集成验收为 **99 项正式测试通过、1 项付费 live 忽略**，fmt/Clippy/WASM 通过。本次仅阅读代码与文档、整理盘点，未重新执行这些测试；验收仍以对应快照和最终审查为准。

## 4. 后续优先级

1. 完成连续 Turn HTTP 写入口与联合验收，闭合第一轮已有两条链路。
2. 回到项目书的 Host 主线：先确定最小 manifest/Context/Registry/依赖与可撤销生命周期契约，再接一个只读工具和一个需逐次审批的工具，验证权限、取消、卸载及重启行为。不要同时扩展全部工具和 UI。
3. 补齐 Workspace/Diff/Checkpoint 与开发者 CLI，跑通“选择项目 → 对话 → 读代码 → 批准写入/命令 → 修改/测试 → 查看 Diff → 接受或恢复 → 重启继续”。

以上是架构优先级，不代表本次已派发新任务或改变员工文件所有权。后续仍由负责人冻结契约、用户分发提示词、Grok 员工编写与测试。
