## 3. 数据契约

### 3.1 声明与版本

公开 `CatalogManifestV1`，从UTF-8 JSON字符串解析；声明类型的根和嵌套struct拒绝未知字段、错误类型或缺字段。config_schema是开放JSON对象，允许任意成员名，本轮不校验JSON Schema语义。**整个输入JSON所有object（含config_schema及数组内object）都拒绝重复成员名**，不能经serde_json::Value静默保留最后值；可在本模块用serde Visitor先校验/构造不含重复键的值，再反序列化typed声明，无需新依赖。返回自有typed错误，不用panic/字符串匹配分类。

| 字段 | 类型 / 语义 |
| --- | --- |
| manifest_version | 整数，必须为1；其他值UnsupportedManifestVersion |
| id | 稳定插件ID，1～64 ASCII字节；首字符小写字母或数字，其余仅小写字母/数字/点/下划线/连字符 |
| display_name | 非空白、无控制字符、最多200 UTF-8字节；不参与解析或绑定身份 |
| version | `ExactVersion {major:u32,minor:u32,patch:u32}`，每项必填 |
| scope | `host` / `project` / `session`，是声明适用的作用域种类 |
| runtime | `builtin` / `wasm` / `process`，本轮仅记录，不执行或加载 |
| lifecycle | 固定 `host_managed`，声明未来生命周期由Host管理，不代表本轮已实现 |
| surfaces | 非空、无重复，元素限 `cli` / `desktop` / `headless` |
| permissions | 无重复的合法名字数组，可空；只声明，不创建批准状态或能力句柄 |
| config_schema | JSON对象，可为空；仅携带配置模式元数据，不验证完整JSON Schema、不存实际凭据配置 |
| provides / requires | `InterfaceKey` 数组，可空；各自内部不能出现完全相同的重复key |

`InterfaceKey = {kind,name,version}`，kind为service/command/query/event/resource/capability六种之一；name为1～128 ASCII字节，首字符小写字母或数字，其余与插件ID字符集相同；permissions名字沿用此规则。version同样是ExactVersion。

**本轮只支持三个数字的精确相等，不支持字符串版本、范围、通配符或预发布，不宣称完整SemVer兼容。** 插件版本与接口版本分开；consumer需要的是InterfaceKey，不能把插件版本误当接口版本。例：插件版本2.0.0可提供接口1.0.0。

提供项不同kind互不满足；相同kind/name的不同版本可同时存在。同一声明可提供多个版本；完全相同key重复拒绝。不同插件提供同一key允许登记，解析时报告歧义，不能注册时覆盖或选择第一个。

### 3.2 作用域

`ScopeKey` 为Host、Project{project_id}、Session{project_id,session_id}；目录创建时绑定唯一ScopeKey，之后不可变。Project/Session ID遵守现有稳定ID的长度1～128 UTF-8字节、无空白/控制/已知敏感值规则（可调用只读的 `secrets::validate_persisted_id`）。这只是身份格式，不去数据库验证其存在。

每个目录只接受scope种类与自身一致的声明；其他种类为ScopeMismatch。两个Project或两个Session是不同目录实例，禁止全局共享注册表、父作用域回退或自动跨目录寻找提供者。不以路径/显示名/legacy Run推断Scope。该值对象不是已实现的Host Context服务容器。

### 3.3 公开API与输出

语义固定，Rust签名可选借用/owned以保持实现清晰，但须提供这些可被集成测试调用的入口：

- `parse_manifest(json: &str) -> Result<CatalogManifestV1, CatalogError>`：严格解析并验证；失败不打印原始JSON或config_schema内容。
- `PluginCatalog::new(scope: ScopeKey) -> Result<PluginCatalog, CatalogError>`：验证scope身份，建立空目录。
- `register(&mut self, manifest: CatalogManifestV1) -> Result<(), CatalogError>`：即便调用者直接构造struct也完整校验，之后一次写入；同目录同id（版本相同或不同）一律DuplicatePlugin，无静默替换。允许依赖尚未登记及循环存在，交resolve诊断。
- `remove_descriptor(&mut self, id: &str) -> Result<CatalogManifestV1, CatalogError>`：只移除指定声明；不存在为UnknownPlugin且目录不变；可移除被依赖者，后续resolve反映缺失。不得命名为unload或触发实际卸载。
- `descriptors(&self)`：按id排序的只读快照/不可变读取，不允许调用者绕过register修改目录。
- `resolve(&self, roots: &[String]) -> Result<ResolutionPlan, CatalogError>`：不修改目录；重复root去重、按稳定id处理，空roots返回空计划；合法但未登记root为UnknownRoot。不隐式解析全部插件。

`ResolutionPlan` 包含scope、`ordered_plugins: Vec<PluginRef{id,version}>`、`bindings: Vec<DependencyBinding{consumer_id,requirement:InterfaceKey,provider_id,provider_version}>`。每个成功绑定明确提供者稳定ID和插件版本；不得只有显示名。bindings按consumer_id、kind序号、name、接口数字版本、provider_id排序；kind顺序固定为service、command、query、event、resource、capability。

计划是不可变普通数据快照，不持有运行实例/授权/外部句柄。目录移除或换提供者后，旧计划可以作为历史值保留，但不能当作可继续执行的授权；后续运行时必须重新绑定/校验版本。移除旧提供者后注册新ID的等价接口提供者，重新resolve应明确显示新provider_id，不按旧显示名“续接”。

## 4. 算法与错误

先从roots收集可达需求。对每个consumer的每个requirement：按(kind,name)找候选 → 精确接口版本过滤 → 0/1/多的确定分类；恰好1则绑定，并递归解析提供者自己的requires。插件依赖方向为consumer依赖provider，最终拓扑边按provider→consumer输出。

- 无同kind/name候选：MissingDependency。
- 有同kind/name但无目标版本：VersionMismatch，列实际可用版本（数字三元组排序去重）。
- 有多个精确候选：AmbiguousProvider，列按id排序的提供者，禁止按注册顺序选第一个。
- 唯一匹配提供者等于consumer时形成自环，不忽略；跨多接口绑定同一提供者只增加一个拓扑依赖边，bindings仍逐需求保留。
- 只在roots的传递闭包内报告缺失/歧义/环。未被选择且不可达的坏插件不能污染另一个健康root的计划。
- 拓扑排序所有已就绪节点按稳定id升序选择，provider必须先于consumer；插入顺序、roots顺序与显示名不改变结果。
- 环诊断返回真实闭合路径（首尾相同，每一跳都有consumer→provider依赖），遍历节点/邻接表均按id排序以稳定复现。不能把所有Kahn未输出节点当成环，因为其中可能有环外消费者。

至少有稳定CatalogError变体：InvalidManifest（字段路径/安全原因）、UnsupportedManifestVersion、DuplicatePlugin、ScopeMismatch、UnknownPlugin、UnknownRoot、MissingDependency、VersionMismatch、AmbiguousProvider、DependencyCycle。需求错误含consumer稳定ID及完整需求键；歧义/版本/环证据可供调用方程序判断，不要求解析中文Display。JSON解码失败归InvalidManifest。多故障时roots按id升序，requires按kind固定序号、name、版本三元组排序遍历，明确当前第一个错误；本轮不要求收集全部错误。

register先检查字段/重复项/scope/已有id，再原子插入；失败前后目录快照相同。resolve只能使用目录快照，没有文件、网络、数据库、Provider、进程、时钟或环境变量读取；不把permissions/config_schema用作操作指令。注册/解析本身的语义无需真实凭据、付费模型或运行插件。
