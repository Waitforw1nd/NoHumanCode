## 并发及准入

`plugin_management.rs:130` 使用 IMMEDIATE 事务，先全局 key 查 receipt，再比较参数和 revision；同 key 同参重放返回原 receipt，冲突不得驱动生命周期。双 Store 同 revision 不同 key 竞争只允许一个成功，另一个 revision 冲突；跨不同 ID 或参数的同 key 竞争只允许一个原始结果，其他冲突。保留历史 receipt 与 key 全局唯一性。

对两个独立 Store/Engine 设屏障，覆盖禁用提交前后与 Agent/Provider 新 lease 准入双向交错：提交后不能由另一旧内存 runtime 发新 lease，既有 lease 按既定 drain 语义完成；重放不能重复启停。测试禁用提交后、生命周期应用前及在途进程崩溃，重启 desired=false 时不激活。Agent draining 与 Provider 既有生命周期分别断言；Models/Balance 不受影响、route-check Models receipt 保持一致。核查网络、预算、审批和工具 claim 与准入失败的副作用和回执。

进程内 mutex 不提供跨 Store/进程一致性。需要冻结持久 desired 和最终短同步准入的线性化点；仅先查询再发 lease 存在 TOCTOU，必须定义与网络/预算/工具 claim 的原子关系，必要时引入持久 claim 或版本协议。审计 runtime lock→Store 锁序，禁止 Store 反取 runtime、持锁 await 或调用未知回调；实现细节须由经理与 owner 决定，预审不声称现设计已满足。
