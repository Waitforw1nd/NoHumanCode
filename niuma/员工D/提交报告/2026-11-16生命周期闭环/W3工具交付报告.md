## 实现行为

1. 从脚本所在仓库相对解析所有路径，输出强制 E；独占共享 git-common-dir 下既有 `nhc-heavy-window.lock`。精确绑定候选 HEAD、产品/Rust 双tree、干净输入和前后原源码 SHA256。
2. 仅构建 worker，从当次 Cargo JSON 选择唯一、非测试、精确 bin/source 对应且位于指定 target 内的 executable，并要求唯一成功 build-finished。独立复制到新 staging，fsync、比对源/副本 hash 与单链接状态；不用旧 target 扫描或硬链接。
3. 仅下一次 Host 编译注入该冻结副本的摘要。两次相同 profile、固定 target、默认 features 和原源码；每次前后重核源码。Host 构建后再次核 worker 副本，复制 Host，写入 pair.json。
4. stage 与最终 pair 同父目录；完整校验后只 rename 到新的 pair 名，不覆盖既有包、不改 current 指针、不安装。worker/Host失败、unknown、源变化、冻结副本篡改或目的目录竞争均停止，原包不变，partial staging/log/gate保留。
5. 复用生命周期监督者，每步总deadline默认1800秒，范围1..7200。timeout/interrupt/unknown 后不开始下一步；原监督者持原 Popen 与日志至直接终态。成功和失败都保留 gate，后代清理由经理原执行会话核实后归档；没有按PID杀、按年龄解锁或“直接exit0证明树清理”。

pair 记录两份工件 hash、候选/source hash、profile/target/features、Host编译输入、源码协议版本，并固定 `runtime_binding_verified: false`。记录输入和字节不等于运行绑定通过，也不提供签名或抵御同权限恶意改写的存储保护。现有公开 `run_wasm` 拒绝门保持。
