# W3 工具安全边界复审

2026-11-16，D；固定工具候选e3045696及补丁1c93f862，只读代码与既有19项mock证据。本轮额外只做内存Path.read_text mock，未改产品、启动Cargo、真实worker或占全局gate。结果见 `W3词法前置边界mock.json`。

| 边界 | 已有保障 | 仍须保留的限制/后续验收 |
| --- | --- | --- |
| 工件形成顺序 | worker先构建，选当次唯一bin/source Cargo artifact；独立copy/fsync/hash，Host仅接该副本摘要，最终重核两份副本 | 这是受控源码/工具链构建的字节链。未对任意Cargo工具、编译器wrapper或恶意同权限写入者建立认证边界 |
| 候选与输入 | 精确HEAD/双tree、clean输入和前后源码清单一致；固定target/profile/default features；输出E盘且相互不重叠 | 全部编译环境及全局Cargo配置未被源码tree穷尽固定；生产分发前需固定/登记工具链、RUSTFLAGS/wrapper/外部配置等实际输入，不能声称可复现或供应链签名 |
| 前置消费者 | 当前main缺Host消费者时编译前失败，有preflight failed/build_started:false；注释/字符串不会冒充消费者 | 词法检查会接受cfg禁用或完全未使用的option_env const。本轮两条内存反例确认此边界，缺消费者对照确实拒绝。该前置不是Rust语义/实际bootstrap使用证明，不能作为生产开放门 |
| 包核验 | verify_pair核固定三文件、候选、工件hash/长度/单链接、Host输入等于worker摘要 | pair.json是包内自描述；若包和清单一起被改写，仅此校验不能认证原构建出处。后续必须由受信外部工件摘要/批准证据绑定包，并在Host实际pin/身份/协议验收；不得把自算hash当可信摘要 |
| 失败与发布 | 新stage、新pair，Windows同父目录rename；不替换旧pair/current，不安装。构建失败/unknown/源码或副本漂移均停，旧包保留 | 完整pair rename后若写manifest失败，可能留下完整但没有成功证据的pair。后续消费者必须要求完整且匹配的独立成功证据，不可仅因目录存在就采纳 |
| 冻结语义 | 与mutable target无硬链接，目标后续重建不影响副本；发布前再次hash | 不是ACL只读、文件handle pin或防同权限竞争保证。前后hash也不证明期间没有短暂修改；受信目录和实际运行期pin仍须后续产品链路完成 |
| 监督与gate | 每步deadline；unknown后同监督者持原Popen至直接终态，不开始下一步；成功失败均留gate给经理 | 直接退出不证明后代全树清理，nonce/gate是协作互斥协议而非对恶意同用户进程的身份认证。无需另造第二owner/安装器补偿此边界 |

复审结论：候选可作为独立工具侧staging切片审阅，仍不是“受信生产绑定已完成”。上述词法与包内自描述限制必须列为下一生产切片的拒绝混搭、缺摘要、错hash、禁用cfg、旧协议和原文件pin验收条件。当前runtime_binding_verified恒false、公开run_wasm拒绝、B main不接线保持正确。没有证据支持把准备成功升级为运行绑定成功；本轮不修改其产品实现。
