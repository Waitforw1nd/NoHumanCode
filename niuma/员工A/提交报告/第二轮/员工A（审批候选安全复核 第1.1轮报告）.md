## 1. B-R2-REDACT-01

固定候选在 `src/store.rs:1042-1083` 修改 `finish_approval`：

1. 将执行结果解析为 `Value`，无法解析时保留为 JSON 字符串值。
2. 只对该结构化值调用一次 `redact_persisted`，得到共同的安全语义值。
3. `stable_safe_json` 为 tool message 生成稳定字符串；事件直接保存同一个安全 `Value`。
4. 完成事务提交后将该稳定字符串返回 Engine，`src/engine.rs:847-854` 将返回值写入当前内存 Task，避免数据库、事件和进程内消息继续使用三份不同表示。

`stable_safe_json` 在 `src/store.rs:1139-1172` 分两路：普通 JSON 若经任务级字符串脱敏仍不变，直接使用紧凑 JSON；会被二次文本脱敏改变的结果则在结构化脱敏后将全部 JSON 字符串片段编码为 UTF-16 `\uXXXX`。函数随后同时断言编码能解析回原安全 `Value`，且再次作为任务字符串经过 `redact_persisted` 时保持不变。因此第1.0轮中 bearer 文本吞掉 JSON 尾部分隔符的路径被切断，repository finished 校验看到的消息解析值与事件 `result` 同义。

新增单元 `safe_tool_result_json_is_stable_and_roundtrips_unicode` 覆盖：普通结果保持原紧凑表示；含 `bearer [redacted]`、换行、中文和 emoji 的非零退出结果能 round-trip 且二次脱敏稳定；普通错误对象保持错误语义。

新增集成 `redacted_command_result_stays_finished_across_restart` 使用真实 `run_command`，产生一次文件副作用、bearer stdout、普通 stderr 和 `exit 7`。它断言：任务完成、审批 finished、消息可解析且 `exit_code=7`、stdout 已脱敏、stderr 保留、事件结果等于消息解析值、只执行一次；随后真正 shutdown runtime、重开 Store/Engine、recover 和 resume，仍 finished 且不重复执行。该测试直接覆盖原反例，而非仅调用脱敏 helper。

边界：测试对主 SQLite 文件做字节扫描不能单独证明 WAL/自由页中绝无历史字节，但功能路径已在进入事务前结构化脱敏，消息与事件断言验证的是数据库公开读取结果。本轮没有把该字节扫描当作完整取证保证。Unicode 编码会降低敏感结果消息的可读存储形式，但解析语义保持不变，属于当前安全稳定化取舍，不是本轮阻断项。

## 2. B-R2-CANCEL-01

固定候选 `src/engine.rs:967-974` 仍先调用持久 `cancel_pending_approvals`，随后只在 active map 存在 handle 时通知 cancellation token；没有 active worker 时也返回 `Ok(())`。未知 task 仍由 Store 查询失败返回错误，避免把不存在对象误报为成功。

新增 `ap08_restart_public_cancel_is_idempotent_without_active_runtime` 同时覆盖 pending 和 approved+not_started：旧 current-thread runtime 中建卡后调用 `shutdown_timeout`，再新建 runtime、Store 和 Engine，recover 后确认 Task 是 `interrupted`；通过公开 `Engine::cancel` 连续取消两次均成功，未知 task 仍失败。测试共同断言 pending 只产生一次 resolved，approved 决定不被改写、两类 execution_state 均为 cancelled、零 `tool_start`、零文件副作用，Task 保持 `interrupted`。随后 resume 生成安全取消 tool 结果而不执行工具。

该夹具真实跨 runtime，且新 Engine 的 active map 为空，能够在旧实现的 `.context("成员当前没有运行中的任务")?` 处稳定失败。因此它不是只调 Store 绕过公开入口，也没有通过新增非法 `interrupted -> cancelled` 转移规避问题。
