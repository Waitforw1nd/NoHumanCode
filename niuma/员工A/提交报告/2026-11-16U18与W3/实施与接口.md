# A：U18 持久执行权候选

基线 `1d09a551`。本树实现 schema18 `execution_owner` 与 `execution-owner-v18` marker，正常 schema17 经原 Windows 域排他锁直接升级；只新增元数据，不重写历史业务行。`open_shared` 和同域再次打开只验证并复用原 owner，不取得 controller 或操作票。身份使用现有 pinned 文件的卷序列号和文件 ID。

claim 先在 admission 中预留唯一 controller，释放该锁后通过单独连接开启 IMMEDIATE 登记新 epoch/recovering。恢复在 IMMEDIATE 事务内核对同 controller/域/epoch，执行现有恢复和验证，并在该事务转 active；提交成功后才开放 admission。错误提交、持久身份/phase/epoch异常及资源 unknown 封门；正常关闭、取消、跨域请求拒绝不人为制造 unknown。controller drop 后仍由原 in-flight 和 unknown 阻止新 controller。

事务先获取 Store DB/SQLite 写锁，随后短暂取得 operation -> admission 锁；释放内存锁后做持久校验。claim/恢复/close 不持内存锁等待 SQLite 写锁。`execution_fence[_for]` 只允许开放时新工作；`execution_settlement_fence[_for]` 允许关闭或取消后持原票收束，但不允许 unknown、跨域、旧 epoch 或错误 phase；`commit_execution_tx` 在提交不确定时封门。显式票 `ExecutionOperation` 持有同一 owner 和捕获 epoch；`seal_unknown` 与 `execution_generation` 复用原 operation / Supervisor 生命周期。注册 C/D 已实现模块，合并各自提交后才能在组合树编译。

Store 中运行/turn 创建、resume、审批、工作区 claim、工具结果、投影与 checkpoint 等相关事务增加 fence 和不确定提交处理。同步审批及取消提供 `_for` 显式票变体；B 负责 Host 入口获取/传播票与多 worker、network body 真实持票，D 负责 worker 的监督及实际收束。配置和查询维持独立。具体覆盖、同步取消及 shutdown 票传递须结合 B 候选联合审查；本提交不声称全部 U/W3 已验收。

验证：只做静态阅读、`rustfmt --edition 2024 --config skip_children=true` 和 `git diff --check`；未执行 Cargo、真实进程、探针、安装或发布。C 编写独立迁移、跨域、取消、恢复停点反例，经理负责组合编译和重型验证；旧测试中主动降版本的夹具可能需移除 schema18 marker/表。B/C/D 模块与改动在各自树，尚未纳入本提交。锁序已交 B 互审，D 的双边界原 holder 收束契约已反馈。

## 组合静审补修

unknown 曾只保存在弱注册的 owner 内，全部外部 Arc 释放后可能丢失原域锁。现对 operation/generation unknown、持久元数据损坏和提交不确定等封门路径保留同一个强 owner 至进程退出；真实网络、进程、I/O 的原对象和实际收束仍须由其监督器持有，owner 保留不能作为收束证明。确定的取消、关闭及跨域拒绝不触发此保留。

`Store::insert_project/session/agent` 为实体创建，不视为普通配置：分别在 IMMEDIATE 事务内核实原票并提交，提交失败封门。当前生产项目配置入口另走 `project_config` 自有事务，已通知 B 审核；现有测试夹具需转真实票或明确历史 SQL fixture。C 已新增 owner/drop 与跨进程锁反例，结果等待经理执行。仅运行 rustfmt 与 diff-check，未运行 Cargo 或真实进程。
