## 1. 结果与责任范围

员工 A 第一轮负责 Project / Session / Turn 领域契约与 SQLite Repository。最初任务明确排除 Engine/server；后续审查逐步把组合命令、状态机和实际调用接入列为基础放行依赖。这一范围变化需要由负责人承担协调和记录责任。

第 1.0～1.5 轮经历返工，最终通过针对 `8f0ccdc` 加用户授权负责人直接补齐后的工作区代码。不能写成“员工 A 第 1.5 轮自行全部完成”。A 建立了基础对象、迁移、投影和多轮修复；负责人最后补齐链路并组织最终测试。

最终证据为 71 项测试通过、1 项付费在线测试未执行，以及格式、Clippy、WASM 检查通过。这是基础交付通过，Approval、插件生命周期、完整 CLI、持久调度等仍需各自开发和验收。

## 3. 实现侧的反思

### 一个函数修好，不代表整个能力修好

幂等从查询修到提交，再从 Store 修到 Engine；脱敏从事件修到保存，再到首次创建、标题和 Agent。遗漏往往在另一条公开或兼容路径。

改进：对每个不变量列一张调用链表：产品入口 → Engine → Store → Repository → 兼容入口 → 原始数据库 → 回读。报告“完成”前确认所有可达入口采用同一语义，而不是靠调用者记住约定。

### 有表、有枚举和有接口，不等于能力落地

依赖表存在，不代表提交会写、查询会返回、调度会按 ID 使用；状态枚举存在，不代表转换合法、事件原子；新增领域对象，也不代表 Engine 实际创建它们。

改进：每个能力同时给出实际调用入口、持久化变化和观察结果。明确哪些只是契约壳，哪些已经接入运行链路。

### 验证要针对不变量的含义

索引名字不证明 UNIQUE，列名齐全不证明外键，两个查询返回同一个 Turn 不证明它们是同一个 Task。

改进：先说明必须成立的事实，再构造能违反它的坏状态。例如同 Turn 的两个 Task 交叉占用 ID、同名普通索引冒充唯一索引、正常依赖更新失败后外层仍提交。错误路径还要断言原数据不变。

### 测试必须证明自己命中了目标

原有门禁多轮通过，但核心场景仍未覆盖。测试夹具自身的归属错误也可能让调用提前失败；应先确保夹具能真正到达待验证分支，不能放宽生产规则来迁就夹具。

改进：失败测试同时证明“前置数据有效、触发条件成立、错误类别符合预期、持久化未受损”。跨层链路还要检查对象数量、事件和模型调用次数。只断言 `is_err()` 容易把无关错误当成证据。

### 事务应由负责该不变量的命令持有

先修改再校验、状态与事件分别提交、可绕过的下层写入口，都会使正确性依赖每个调用方的习惯。

改进：复合创建、状态变化、恢复和继续封装为命令；内部依赖替换使用保存点保护；测试异常后继续提交的情况。模块边界承担不变量，调用者只表达意图。

### 报告措辞要与证据强度一致

“全量结构检查”和“只验必要列”不是同一件事。诚实写明延期比宣称完成更有用，但员工也不能单方面把放行必需项延期后要求通过。

改进：用验收编号逐项关联实现入口和测试，分别标记已验证、待验证、未实现、经确认延期。引用上一轮结果时写清是历史结果，不冒充本轮重跑。

## 4. 负责人和审查方的反思

1. **范围变化要明示。** A 最初不改 Engine/server，后续整体基础验收需要接入。应当更新任务、划清 A/B/C 接口或由负责人组织集成，不能让员工在不变的任务单下面对不断增大的交付面。
2. **两次未修好就要给具体修法。** 不能持续重复“统一幂等”“补齐校验”。需要给统一分类算法、schema 元数据结构、两候选身份裁决、事务顺序和测试矩阵，并沿用同一个问题编号追踪。
3. **审查意见也可能不严谨。** 历史审查仅凭 `APIKey` 的归一化结果推断泄漏，没有充分说明其他后缀规则；“多个字段同值必然造成漏测”也不成立。能确认的是重复 JSON key 会覆盖，独立字段/不同值有助于定位。新规范不把这些过度推断当作事实继承。
4. **推荐算法不能含糊。** 任务解析应明确为：分别取得 canonical ID 与 legacy ID 候选，两者都检查后按真实 Task 行身份裁决。不能一面说“首次命中就返回”，一面又要求发现双命中冲突。
5. **安全承诺要有边界。** 已知格式和字段可拒绝/脱敏，结构化凭据应进入 DPAPI；不能保证识别任意文本中的未知秘密。最终发现的 Authorization scheme 漏脱敏是具体可复现问题，已经修复；它与无限扩大敏感词列表是两回事。
6. **最终通过要精确归属。** 记录是谁补齐、通过的是哪一版、哪些测试未执行、哪些业务仍未交付。不能因为用户希望尽快通过而省略实际验证，也不能无止境扩大验收范围。
