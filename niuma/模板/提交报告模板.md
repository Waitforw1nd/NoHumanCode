# <角色>：<任务> 第<轮次>轮提交报告

日期：<日期>；作者：<实际作者>；状态：<提交待审/返工提交/完成文档整理等>。

1. 当前任务与代码基线：链接任务，记录 Git 模式、分支、工作树相对位置、完整基线/候选实现 SHA、Git 操作者与文件所有权；未提交时写清 HEAD、继承修改及文件哈希，不虚构提交。
2. 验收对应：逐条列“要求 → 实现入口 → 证据 → 已完成/未完成/未验证”。
3. 变更范围：文件、API/事件/schema/权限/凭据/兼容影响，无变化也写明。
4. 失败与恢复：异常、取消、重试、并发、恢复相关行为。
5. 实际验证：实测版本、命令、结果、退出码、日志位置；没有执行的项目及原因。候选提交之后的差异需说明是否改变源码/测试/构建输入。
6. 未完成、风险、负责人需决定事项；不得自行宣告员工验收通过。
7. 交接：本人身份已更新的日期/版本、下一步第一条操作、不要重做的事项。
