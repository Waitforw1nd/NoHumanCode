## 安全与存储契约

1. 仅追踪批准后真实执行的 `write_file`。读取、拒绝、取消及审批前不得创建备份或变更记录。绑定 task+tool_call；同任务同规范化路径聚合展示最早 before 与最新成功 after。Windows 路径别名不能绕过冲突/唯一性。`run_command` 不纳入保证。
2. schema 7→8 原子保全迁移，保留已有业务行、审批、事件及 schema6→7 的安全检查。新表真实检查列、唯一/FK/CHECK/index，不只检查名称。保存受保护的原始 before 字节、明确的原不存在状态、before/after 摘要、工作区/路径及写入状态。使用现有 DPAPI；加密不可用/解密失败 fail closed，不用明文 fallback。可限定原文件和新写入 <=256 KiB UTF-8；不支持的输入必须在文件副作用前明确拒绝，不能静默漏追踪。
3. 写前持久准备，写后事实与审批 finish、结果、消息、投影在同一事务完成。失败的准备记录不能冒充成功；崩溃/提交失败的结果不明为 unknown，禁止自动重做或自动恢复。原审批 claim/unknown 语义保持。
4. 新 file_backup/变更/恢复事件仅安全元数据，禁止保存 before 正文、密文、原始参数或未脱敏内容。HTTP DTO 不含正文、密文、原始绝对路径。旧 file_backup 历史保持只读，不回填伪造精确 before；无可信新记录的旧备份明确不可恢复，禁止写回脱敏替代值。
5. `changes` 返回 typed DTO：至少稳定 change_id、task_id、相对 path、kind(created/modified)、before/after 摘要、执行/恢复状态、current 状态与 restorable。缺失、内容分歧、不可读、非法路径、unknown、已恢复明确区分，不能把 IO/非UTF8/链接错误伪装成 missing。只读不改变任务/变更事实。
6. `restore` 仅非运行任务，和本 Host 的其他 write_file、恢复、resume/start 协调互斥，不能仅瞬时查看 active 后释放。首次 task 前镜像是恢复目标；执行前全量预检所有候选 root、当前有效权限 scope、路径/链接、当前字节摘要等；任一冲突整批零文件写。task A→B 修改后 A 恢复必须冲突；新文件被用户修改后不能删除。准备之后每文件副作用前复查。
7. 同目录临时文件安全替换，不原地截断硬链接；禁止通过 symlink/junction/reparse 点越界。删除只可删除仍匹配任务产物的目录项。静态验证与 Host 内并发协调必须实现；不宣称抵御具备本机文件系统写权限的恶意进程在最后检查与 OS 调用间的任意竞态，报告明确该边界。
8. 恢复先持久 claim，逐文件持久 outcome，事件与状态同事务。多文件不是数据库式文件系统原子事务：预检失败零写；执行中故障返回明确 partial/unknown 和各路径事实，不用普通成功计数掩盖。重启后 claimed 恢复为 unknown；不猜测成功、不自动重试。重复已完成恢复为幂等明确结果，文件后续再次被编辑也不得覆写。恢复过程禁止 provider 调用/审批绕过。

## typed API 与 HTTP

公开 DTO/error 放新模块；Engine 提供 typed changes/restore（允许替换原同名返回值），报告写真实签名。业务错误至少 NotFound、Conflict/Active、Unrestorable/Unknown、Corrupt/Internal 可区分，不解析中文字符串。内部错误不暴露 SQL/路径/秘密。

GET `/api/tasks/{id}/changes` 保持 `{"changes":[...]}` 包装，内容改上述安全 DTO；这是有意移除旧 previous/current 正文，不兼容字段变更要写报告。POST `/api/tasks/{id}/restore` 返回明确 typed restore receipt，可保留 ok/restored 加状态与逐文件结果；complete 才 ok=true，partial/unknown 不冒充完整成功。无记录可 complete/0；旧不安全备份返回不可恢复冲突。两路由用现有 persisted id 校验/Host/Origin/token/安全头；已知 NotFound404，冲突/活动/不可恢复/unknown409，内部500；固定结构化安全错误。partial 使用409并携带安全逐文件 receipt，必须有测试。不扩其他 HTTP 接口语义。
