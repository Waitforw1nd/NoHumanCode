## 原因及静态改动

- R03：原 stderr 的三个固定文本断言失败；`commit_tool_result` 将非 JSON 的审批错误解析为字符串后统一 JSON 序列化，导致消息多一层引号，事件仍为原字符串。候选对审批拒绝、取消、无 claim 中断仅保存原固定文本；HostDenied 消息表示不变。重放、事件对账和 Chat 闭合使用 JSON 解析成功取值、否则原字符串的统一比较，来源、状态和精确固定内容约束保留；合法 JSON 字符串 `"null"`、`"123"` 不被误判为 null/数字。已有其他 JSON 结果及对象/数组继续安全序列化。

- 候选在唯一 Task 安全边界对合法 function 对象参数先结构化脱敏，再按需稳定编码，外层原有脱敏仍覆盖普通消息与其他字段；原始密钥不通过只编码来保存。合法且结构与文本扫描均安全的旧参数保留原始文本，避免因空白和键序变化破坏旧 Chat 前缀。无效或非对象参数不猜补；未知损坏历史不批量重写。瞬时调用与 Store 绑定以同一个结构化安全对象比较，原调用摘要、v2 绑定、scope、调用次序、事务重读和闭集安全证明仍在。Store 内当前调用比较两侧均经相同 Task 安全边界。
