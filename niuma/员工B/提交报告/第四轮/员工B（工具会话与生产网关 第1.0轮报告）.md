## 最终行为与 API

1. `Store::run_context(&str) -> anyhow::Result<RunContext>` 使用 DB 锁内一致读事务；返回真实 Project/Session/latest Turn/TurnTask，latest 使用首事件最小 seq 的提交顺序。`RunContextError::{NotFound, Unmapped, CorruptState}` 区分缺失、旧未映射和损坏，SQLite 操作错误 source 保留。RunContext 可 Serialize，不猜 ID。
2. `send_chat_turn` / `append_chat_turn` 先做原 key 回放，再限制 completed、Chat、单 Agent/Task、无依赖；完整继承 route/workspace/name/role/tools/write_scopes/allow_commands/max_rounds。Host workspace 必须与 Project 和前 Task 一致；现有 scope 冲突检查保留。事务内重复核对前序、身份、权限和消息快照。
3. 全 Session 历史按照 MIN(events.seq) 扫描；每个后继必须保存旧完整消息前缀。工具 group、参数对象、call ID、结果顺序、闭合与唯一性逐项验证。调用归首次引入的原 Task，结果必须对应原 Task/Turn/Session 的有序 tool_result 事件；历史只读或 denied 的旧事件无 call_id 时，使用其所属 Task、有序位置、名称和精确结果证明来源。新记录补充 tool_call_id。
4. 受控调用必须具有原 Task 的审批；后继不能为继承调用另造或借用审批。新模型重复历史 call ID 在已有 validate_new_tool_group 拒绝，不执行旧调用。经理/D 联合检查发现的历史中断占位特赦已删除：旧 write/command 没有原审批，即便 resume 产生 interrupted 占位并已 completed，仍返回 `UnresolvedEffects`。
5. 扫描所有已关联 Session Task 的 pending、approved 未结束、claimed/unknown 审批，prepared/unknown change，claimed/partial/unknown restore 和 unresolved restore outcome，返回 `ChatTurnError::UnresolvedEffects`。denied/cancelled 有结果、finished、明确 failed change 不归入未决集合。旧 resume 兼容入口未改变。
6. complete restore 后加入 Host 固定生成的 user 角色恢复事实，列明 Task/restore ID 并要求先读当前文件。保留原工具结果，不把用户输入升级为 system 指令；同一 helper 在 Engine 生成和 Store 事务比较使用，幂等回放不追加提示。旧 Task 写封存保持，新 Task before 来源于恢复后的字节。
7. Engine 构造 `ToolRuntime::builtin()`，每轮模型定义、执行前校验及最终调用共用该实例；公开 `disable_builtin_files`、`unload_builtin_files` 委托 runtime。批准前不持 lease；批准后 runtime.acquire 的同步 admit 内实际 claim。原 workspace gate/prepare/finish/cancel 保留，最终执行消耗 `ToolLease`。运行时锁不跨 await，无 Store→runtime 反向嵌套。read/write 真实 payload 来自 D 注册绑定；其余工具仍为明确兼容分支，不宣称全部插件化。
