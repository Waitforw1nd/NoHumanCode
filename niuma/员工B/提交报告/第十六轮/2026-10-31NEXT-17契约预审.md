## 可执行的双阶段策略

本片在真实Engine每轮Completion前后调用受限Agent策略。Before可选Host当轮已允许工具定义的子集，改变模型实际看到的工具；After可决定每个原调用继续进入Host权限策略或拒绝。替换策略能实际改变Provider请求和工具副作用，并通过Host固定结果让模型继续，不是仅搬迁循环。默认builtin选择全部工具、对全部工具调用继续、纯文本完成，保持原行为。

建议冻结的crate-private object-safe接口（名称由经理确定）：

```rust
#[derive(Clone, Copy)]
pub(crate) enum ToolClass { Read, List, Search, Write, Command, Other }
pub(crate) enum StrategyInput<'a> {
    BeforeCompletion { tools: &'a [ToolClass] },
    AfterCompletion { outcome: CompletionKind<'a> },
}
pub(crate) enum CompletionKind<'a> {
    NoToolCalls,
    ToolGroup(&'a [ToolClass]),
}
#[derive(Clone, Copy)]
pub(crate) enum ToolVote { ApplyHostPolicy, Deny }
pub(crate) enum StrategyAction {
    UseTools(Vec<usize>), ToolVotes(Vec<ToolVote>), Finish, Stop,
}
pub(crate) enum StrategyError { Unavailable, InvalidDecision, Failed }
pub(crate) trait AgentStrategy: Send + Sync {
    fn decide(&self, input: StrategyInput<'_>) -> Result<StrategyAction, StrategyError>;
}
```

`ToolClass`由Host从其工具定义或原组按顺序派生；Other不能代表授权。策略不接收参数、对话历史、目标、凭据或执行句柄，不可改变原始定义、历史、模型、网络目标或预算。Before仅接受严格递增、不重复且小于工具定义数量的 `UseTools`，允许空集；Host按索引保序选取完整原定义，后续Provider请求及该轮工具许可均使用此子集。After的NoToolCalls仅接受Finish或Stop；ToolGroup仅接受长度恰等原调用数的ToolVotes或Stop。交叉阶段、越界、乱序、重复、数量不符、异常或panic均为固定安全失败；不得插入/重排调用、构造执行结果或增加权限。向量长度按Host现有工具定义或原组验证；不静默引入额外可见输入上限。

Stop由Host作为固定安全中止走现有失败/取消状态与持久化，不伪造成功。NoToolCalls只在Host已保存原始assistant消息后允许Finish；`Some([])` 是ToolGroup，空投票仍沿原实现进入下一轮，不等同完成。每次首次/后续Completion均调用Before，已结算并按现行ID规则验证、保存assistant消息后调用After；`max_rounds` 和流式delta/usage由Host维持现有语义。若After Stop留下已保存未答工具组，后续显式resume使用既有保守对账，不自动执行或伪造完成。

Host逐项检查取消、原工具name、参数JSON和是否属于该轮选中定义；无论Apply或Deny均按原顺序先做这些检查。Apply进入现有 `execute_or_wait`、审批/claim与ToolRuntime；Deny由Host使用 `record_tool_result` 持久化固定 `{"error":"blocked_by_agent_policy"}`，不得由策略编造结果。当前 `validate_new_tool_group` 仅提前验ID，名称/参数逐项校验；所以第1项可能已执行、第2项畸形才报错。策略不能提前整组解析而改变该前缀行为；如产品要整组原子拒绝，须另定可见语义和验收。

## 任务期lease与恢复

建议PluginHost注册Host scope的 `builtin.chat-agent` provider、`builtin.engine-chat-agent` consumer和Service `agent.strategy` 1.0.0，显式依赖、工厂和payload类型验证。Host在 `run_task` 开头、依赖等待及运行侧副作用之前取得非Clone `AgentLease`；注意Run/Task创建及launch登记已发生，不能称创建也受此lease约束。lease绑定当次策略实例并覆盖reconcile及所有轮次，结束、失败或取消drop后减少in-flight。只在短锁内验证活动绑定、generation、admission和计数，锁外执行同步策略及所有await；复用一次hook/TLS `plugin_callback::guarded` 防止同步panic载荷泄漏，错误/日志固定安全。原生builtin是受信进程内代码，不是恶意第三方沙箱。

关闭关新任务准入、更新generation并按依赖顺序撤销注册项；先前取得lease的Task保留旧策略直至结束或取消，不能把registry撤销说成撤销已发生副作用。长审批等待仍计in-flight、表现draining是明确权衡。新进程默认builtin；本片只读公开runtime状态（包括active、admission、generation、in-flight、draining、transition、failure/recovery），不冒称持久控制。状态对接拟由C负责server只读GET及独立HTTP测试；具体路径、错误形状与唯一owner需经理冻结。

resume和重启重新取得任务lease，失败不进入reconcile或新副作用；成功后先执行既有 `reconcile_open_tools`，对已批准/已执行的遗留调用保留原检查与claim，未有审批记录的未答调用记录中断，unknown不猜测成功或自动重做。策略不重写恢复历史或放宽封存；resume deferred消息和Session/Turn继续沿现有Task兼容路径。Task/Run执行与Store新模型投影不更表、不改schema。取消在各策略调用前后及每项执行前复核；无await或callback中途停止的承诺。

**持久化限制**：当前 `record_tool_result` 先 `store.event` 后 `save_task`，不是同一事务；策略拒绝复用现有路径不能声称事件与消息原子或重启恰好一次。测试应覆盖event成功/save失败并报告实际事实；若要求原子化，另授权Store事务API、历史/故障验证及文件owner，不应由Engine虚称。未知外部执行仍使用既有持久回执裁决。
