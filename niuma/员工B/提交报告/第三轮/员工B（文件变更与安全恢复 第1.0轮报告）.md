## 实现与公共接口

公开接口真实签名使用 `anyhow::Result`，不是以 `WorkspaceChangeError` 为唯一错误类型的别名：

```rust
pub fn changes(&self, id: &str) -> anyhow::Result<Vec<WorkspaceChange>>;
pub fn latest_restore(&self, id: &str) -> anyhow::Result<Option<RestoreReceipt>>;
pub async fn restore(&self, id: &str) -> anyhow::Result<RestoreReceipt>;
```

DTO/error 在 `src/workspace_changes.rs`。业务错误可从 anyhow 错误链 downcast 为 `WorkspaceChangeError::{NotFound, Active, Conflict { receipt }, Unrestorable, Unknown { receipt }, Corrupt, Internal}`，其他内部错误仍可携带 cause。HTTP 统一转换为固定安全消息，不透传 SQL/路径/秘密。`WorkspaceChange` 含 change/task ID、相对 path、kind、before/after 摘要、state、restore_state、current、restorable；prepared/unknown 没有成功 after 时 DTO after_digest 为空字符串，不能视为成功摘要。确定 failed 不进入成功聚合。

GET `/api/tasks/{id}/changes` 返回 `{"changes":[...],"restore":receipt或null}`，有意去除 previous/current 正文，与旧字段不兼容。POST 返回 ok/restored/status/restore_id/outcomes；complete 才 ok=true；partial/unknown 为409且保留安全逐路径 receipt。空 no-op 为 complete/0、restore_id=null且不封存任务；有旧不可信 file_backup 返回不可恢复。已有 operation 的 POST 返回同 receipt，不重做；complete后外部编辑不被覆盖。NotFound404、非法ID400、权限403、活动/冲突/不可恢复/未知409、内部500；现有 Host/Origin/token/安全头保持。

schema7→8 在同事务建立 `workspace_changes`、`workspace_restores`、`workspace_restore_outcomes` 和约束/索引。Store 验证真实列及约束定义、保留字符串字面量，拒绝伪装；schema6链和已有审批安全校验继续。写前持久 prepared，原 before 用 DPAPI 加密；写成功后 finish 事务同步审批、消息、结果事件、change 和任务投影。未完成 prepared 重启变 unknown。恢复先全量路径、权限、绑定、摘要和解密预检，再 claim、逐路径副作用与持久 outcome；中途错误有 partial/unknown，不伪称文件系统多路径原子事务。

## 支持边界与下一步

本片只追踪批准的write_file，恢复普通文件字节与存在性；不支持run_command回滚、ACL/ADS/时间戳/文件identity恢复、目录checkpoint或任意Git差异。原before和新内容均限定<=256 KiB UTF-8；新args若持久化脱敏导致不能精确重核则拒绝，不能执行脱敏替代值。DPAPI不可用或before解密失败fail closed，无明文fallback。

Host共享Engine gate协调write/start/resume/restore，Store事务保持CAS；不支持同一DB多个活跃Engine/Host跨进程互斥。对有本机文件写权限的恶意进程，在最后检查与OS调用间仍有TOCTOU边界，不承诺抵御任意外部竞态。任何已有恢复operation的原task后续write_file被封存，需新task再次写；本片无自动reconcile。
