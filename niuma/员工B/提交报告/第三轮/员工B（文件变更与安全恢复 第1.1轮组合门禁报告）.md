### 第1.0接口字段层级澄清

第1.0对POST字段的简述没有明确嵌套层级，实际 `server.rs::restore` 顶层是 `ok/restored/status/receipt`，**restore_id、task_id、outcomes属于receipt内部**。以下是完整包装形状（ID为说明用示例），不是实际日志中的业务对象：

```json
{
  "ok": true,
  "restored": 1,
  "status": "complete",
  "receipt": {
    "restore_id": "restore-id",
    "task_id": "task-id",
    "status": "complete",
    "restored": 1,
    "outcomes": [
      { "change_id": "change-id", "path": "src/a.txt", "status": "complete" }
    ]
  }
}
```

带receipt的409 partial/unknown在同一包装之外增加固定结构化错误字段；partial示例：

```json
{
  "code": "conflict",
  "message": "工作区内容已变化",
  "error": "工作区内容已变化",
  "retryable": false,
  "ok": false,
  "restored": 1,
  "status": "partial",
  "receipt": {
    "restore_id": "restore-id",
    "task_id": "task-id",
    "status": "partial",
    "restored": 1,
    "outcomes": [
      { "change_id": "change-a", "path": "src/a.txt", "status": "complete" },
      { "change_id": "change-b", "path": "src/b.txt", "status": "unknown" }
    ]
  }
}
```

unknown分支的固定message/error为“恢复结果未知”，receipt也在同一层。GET仍为 `{"changes":[...],"restore":receipt或null}`，字段名是restore；不能把GET的restore与POST的receipt混用。本澄清保留第1.0原文作为当时报告，代码未变化。
